# PRD — ผู้ช่วยวางแผนทริป (AI Trip Planner)

สถานะ: **รออนุมัติจากเจ้าของ** · เขียน 18 พ.ย. 2026 · ชื่อบนจอ: **วางแผนกับผู้ช่วย** · ชื่อในโค้ด: `planner`

ที่มา (เจ้าของ, 18 พ.ย. 2026): "All functions are enough for commercial now or need to add something more? Especially about AI to help."
→ ตกลงว่าช่องว่างใหญ่ที่สุดก่อนขายคือ **ลูกค้าไม่มีคู่มือทริป** → "เอา เขียน PRD AI วางแผนทริปเลย"

---

## 1. ปัญหา

ทุกอย่างที่ดีในแอปห้อยอยู่กับ **แผนทริป**: หน้าวันนี้, ไทม์ไลน์ + เตือนก่อน 30 นาที, กระเป๋าวันนี้, ที่กิน, ภารกิจเด็ก, แผนที่เด็ก,
นิทาน, พาสปอร์ต, คู่มือฉุกเฉิน ตอนนี้แผนมาได้ 3 ทาง:

| ทาง | ใครทำได้ | ผล |
|---|---|---|
| คู่มือ PDF (Trip Operations Manual) → `#/import` | คนที่มีคู่มือแบบเจ้าของ (แทบไม่มีใคร) | เล่มครบ |
| เล่มจากรูป `#/snap` | ทุกคน | เล่มความทรงจำ — แต่ **ไม่มีแผน** ไม่มีหน้าวันนี้ ไม่มีเตือน |
| เล่มเปล่า | ทุกคน | "วันที่ 1…n" ว่างๆ |

ครอบครัวทั่วไปที่ **กำลังจะไปเที่ยว** ไม่มีทางได้ส่วนที่ดีที่สุดของแอป (ใช้ระหว่างทริป) เลย

## 2. เป้าหมาย

พ่อแม่ตอบคำถามสั้นๆ ไม่เกิน 2 นาที → ได้ **เล่มที่วางแผนครบ** ในรูปแบบเดียวกับเล่มฮ่องกง/ออสเตรเลีย
(แผนรายวัน + ไทม์ไลน์มีหัวข้อ, การเดินทาง, ที่กิน, แผนสำรอง, เงินโดยประมาณ, คู่มือพกพา, ภารกิจและนิทานของเด็ก, รูปประจำวันจากคลัง)
ภายใน ~5 นาที แก้ได้ก่อนบันทึก และแก้ทีละวันได้หลังบันทึก

**ไม่ใช่เป้าหมาย:** จองตั๋ว/ที่พัก, เปรียบเทียบราคา, รับประกันว่าข้อมูลถูกต้อง 100 % (บอกชัดว่า "เช็กก่อนไป")

## 3. ผู้ใช้

- **P1 — พ่อแม่ที่จะไปทริปใน 1–8 สัปดาห์** รู้ว่าจะไปไหน ไปกี่วัน อาจจองที่พักแล้วหรือยัง ไม่อยากเขียนแผนเอง
- **P2 — พ่อแม่ที่ยังลังเล** "ญี่ปุ่นหรือไต้หวันดี ลูก 2 ขวบ" → ได้ร่างสองแบบไว้เทียบ (เฟส 3)
- **P3 — เด็ก** ได้ภารกิจ นิทาน แผนที่ เหมือนเล่มที่วางแผนเอง
- ไม่เปลี่ยน: ญาติ (ดูอย่างเดียว), เล่มพิมพ์ PDF

## 4. ประสบการณ์ (flow)

### 4.1 ทางเข้า
- การ์ด "เล่มใหม่" บนชั้นหนังสือ: **วางแผนกับผู้ช่วย** (ใหม่, นำหน้า) · เล่มจากรูป · นำเข้าคู่มือ PDF · เล่มเปล่า
- ขั้นสุดท้ายของการตั้งค่าครั้งแรก (`#/start/5`) เสนอทางนี้ก่อน
- เห็นเฉพาะพ่อแม่ (editors) และเมื่อเปิดผู้ช่วยแล้ว (`ANTHROPIC_API_KEY`)

### 4.2 ขั้นที่ 1 — คำถาม (`#/planner`, หนึ่งหน้า การ์ดแบบหน้าตั้งค่า `pcard`)
1. **ไปไหน** — ช่องพิมพ์อิสระ + ชิปเมืองจากคลังรูป (`GET /api/b/geo`) "โตเกียว", "เชียงใหม่ → ปาย"
2. **วันไหน** — วันแรก–วันสุดท้าย (หรือ "ยังไม่แน่ใจ ประมาณ 5 วัน ธันวา")
3. **ใครไป** — เด็กดึงจากโปรไฟล์ครอบครัวอัตโนมัติ (อายุตอนเดินทาง, ไม่ต้องพิมพ์) + จำนวนผู้ใหญ่ + "มีผู้สูงอายุ"
4. **จังหวะ** — การ์ดเลือก 3 แบบ: สบายๆ (1 ที่เด่น/วัน + งีบ) · ปกติ · เต็มวัน
5. **เดินทางยังไง** — ขนส่งสาธารณะ · เช่ารถ · ผสม
6. **ที่พัก** — "จองแล้ว" (พิมพ์ชื่อ + คืนไหน) หรือ "ให้ผู้ช่วยแนะนำย่าน"
7. **เที่ยวบิน** (ไม่บังคับ) — เวลาถึง/ออก (เวลาเท่านั้น ไม่เก็บเลขที่นั่ง/เลขจอง)
8. **ต้องไป / ไม่เอา** — ช่องพิมพ์อิสระ "ดิสนีย์ 1 วัน", "ไม่เอาเดินเยอะ", "ลูกแพ้ถั่ว"
9. **งบโดยประมาณ** — ประหยัด · กลาง · สบาย (ใช้เลือกร้าน/กิจกรรม ไม่ได้คำนวณเงินจริง)

ปุ่ม **ให้ผู้ช่วยร่างเส้นทาง** + บรรทัดบอกว่าจะส่งอะไรไปให้ผู้ช่วย (ดู §7) และจำนวนครั้งที่จะใช้

### 4.3 ขั้นที่ 2 — โครงทริป (`#/planner/route`, 1 call, ~20 วิ)
ผู้ช่วยตอบเป็น **โครง** ไม่ใช่เล่มเต็ม: แต่ละวัน = เมืองที่นอน + หัวข้อวัน 1 บรรทัด + 2–3 จุดหลัก
แสดงเป็นการ์ดรายวัน (หน้าตาแบบ `.snapdays` ของเล่มจากรูป: รูปเมืองจากคลัง, สีเมือง)
พ่อแม่: สลับวัน, เปลี่ยนจุด, ลบ/เพิ่มวัน, พิมพ์ "วันที่ 3 อยากพักผ่อน" → ส่งโครงใหม่ (1 call)
ปุ่ม **ร่างเล่มเต็ม** (บอกจำนวนครั้งที่จะใช้ก่อนกด)

**ทำไมแยกขั้น:** โครงผิด = เล่มทั้งเล่มผิด และร่างเต็มใช้ ~25 calls โครงใช้ 1 call — แก้ตรงนี้ถูกที่สุด

### 4.4 ขั้นที่ 3 — ร่างเล่มเต็ม (งานเบื้องหลัง ~3–6 นาที)
ใช้ท่อเดียวกับ **นำเข้าคู่มือ PDF** (`server/bookimport.js`) แต่ input คือ "โครง + คำตอบ" แทนข้อความคู่มือ:
`structure` (วันละไทม์ไลน์มี `h` + `go`, legs, picks, planB, money เป็นช่วง) → `info` (คู่มือพกพา) → `restaurants` (2 รอบเหมือน import)
→ `kids` (learn, quiz, tale, ภารกิจ) → `extras` (สัตว์, firsts, คำศัพท์, อาหาร, แผนที่เด็ก) → แปลไทย →
`plan-to-seed-core` (validate · `toSeed` · **privacy scan** · `styleCheck`) → `stockMatch` (รูปประจำวัน, ตราประเทศ, ไกด์ 2 ตัว)
→ แถวใน `book_drafts` (ที่เดียวกับร่างจาก PDF)

หน้าแสดงความคืบหน้าแบบเดียวกับ `#/import` (แถบ, ขั้นที่ทำอยู่) — ปิดแอปได้ เสร็จแล้ว **push** "ร่างเล่มพร้อมแล้ว ✨" (แบบ `push.draft`)

### 4.5 ขั้นที่ 4 — ตรวจและบันทึก
หน้าร่าง (ใช้หน้าของ `#/import` ที่มีอยู่: ปก + สารบัญ + จำนวนจุด/ร้าน/ภารกิจ) + **รายการ "เช็กก่อนไป"** ที่ผู้ช่วยไม่แน่ใจ (§6)
**บันทึกเป็นเล่ม** → `putSeed(c, seed, 'planner')` → เล่มใหม่บนชั้น เหมือนเล่มที่มากับแอปทุกอย่าง
ทุกข้อความที่ผู้ช่วยเขียนติดป้ายเงียบ "ร่างโดยผู้ช่วย" (`aiTag`, พ่อแม่เห็นเท่านั้น ไม่พิมพ์) จนกว่าจะแก้หรือกด "ใช้ร่างนี้"

### 4.6 หลังบันทึก — แก้ทีละวัน (เฟส 2)
บนหน้าวันนี้ของเล่มที่ผู้ช่วยวางแผน: **ขอเปลี่ยนวันนี้** → พิมพ์ "ฝนตก", "ลูกไม่สบาย อยากอยู่ใกล้ที่พัก", "ร้านปิด"
→ ผู้ช่วยเขียนวันนั้นใหม่ (1–2 calls) โดยดู แผนเดิม + ที่พักคืนนี้ + พยากรณ์อากาศสด (`server/weather.js`)
→ แสดงเทียบ เดิม / ใหม่ → กดใช้ → เขียนทับแผนวันนั้น (เก็บของเดิมไว้ย้อนได้ 1 ครั้ง)
**ห้ามเปลี่ยน key ของจุดที่ check-in แล้ว** (กฎ stable keys) — วันที่เริ่มแล้วเพิ่มจุดใหม่ได้ ไม่เปลี่ยนชื่อจุดเดิม

## 5. สิ่งที่ผู้ช่วยต้องทำได้ดี (คุณภาพของแผน)

กฎที่ส่งให้ผู้ช่วยทุกครั้ง (รวมกับ `THAI_STYLE` + `EN_STYLE` + `REPORT_STYLE` ที่มีอยู่):
- **เด็กเล็กมาก่อน:** เคารพเวลางีบ (ไม่มีขาเดินทาง > 80 นาทีช่วงงีบ), อาหารเย็นก่อน 18:30, 1 กิจกรรมหลัก/ครึ่งวันตามจังหวะที่เลือก
- **สมจริงเรื่องเวลา:** ระยะทาง/เวลาเดินทางระหว่างจุดต้องเป็นไปได้ วันมาถึง/วันกลับเบา
- **ทุกจุดมี Google Maps query เต็ม** (`q`) + ชื่อภาษาท้องถิ่นถ้ามี
- **แผนสำรองทุกวัน** (ฝน/ปิด/เด็กเหนื่อย) และ "ถ้า…แล้ว…" ของทริป
- **ราคาเป็นช่วงเสมอ** + "≈" ไม่สร้างตัวเลขเจาะจงที่ไม่รู้
- **ข้อจำกัดเด็ก** (ความสูงเครื่องเล่น, อายุ) บอกเป็น "เช็กที่ทางเข้า" เมื่อไม่แน่ใจ
- ห้ามเลขจอง/เลขเที่ยวบิน/ชื่อเด็กในแผน (privacy scan เดิมจับอยู่แล้ว)

## 6. ความถูกต้อง (ความเสี่ยงหลัก)

ผู้ช่วยอาจเขียนชื่อร้านที่ปิดไปแล้ว เวลาเปิดผิด ราคาเก่า — สำหรับสินค้าที่ขาย นี่คือความเสี่ยงอันดับ 1

| สิ่งที่ทำ | เฟส |
|---|---|
| ทุกเวลาเปิด-ปิด/ราคา/ความสูง ติดป้าย "เช็กก่อนไป" + รวมเป็นรายการในหน้าตรวจร่าง | 1 |
| **เบอร์ฉุกเฉิน, ปลั๊กไฟ, สกุลเงิน, วีซ่าคนไทย** มาจาก **ตารางของเราเอง** ต่อประเทศ (`server/countryfacts.js`, ตรวจโดยคน) — ไม่ให้ผู้ช่วยแต่ง | 1 |
| ร้านอาหาร: แนะนำ **ย่าน + ประเภท** เป็นหลัก ชื่อร้านเฉพาะเมื่อมั่นใจ (ร้านดัง/เปิดมานาน) | 1 |
| **ค้นเว็บยืนยัน** (Claude web search tool) ก่อนใส่ชื่อร้าน/เวลาเปิด — ส่งแค่ชื่อสถานที่+เมือง | 3 (ต้องอนุมัติ ดู §11) |
| ส่วนท้ายทุกวัน: "จากผู้ช่วย · ราคาและเวลาเปิดเช็กซ้ำก่อนไป" (แบบ `.dfoot`) | 1 |

## 7. ความเป็นส่วนตัว (PDPA)

ส่งให้ผู้ช่วย: ปลายทาง, วันที่, **อายุเด็ก (ไม่ใช่ชื่อ)**, จำนวนผู้ใหญ่, จังหวะ/งบ/การเดินทาง, ชื่อที่พักที่พิมพ์เอง, ข้อความ "ต้องไป/ไม่เอา"
ไม่ส่ง: ชื่อเด็ก, รูป, ความทรงจำ, เลขจอง, เบอร์โทร
ชื่อเด็กใส่กลับในเครื่องตอนสร้างเล่ม (ข้อความภารกิจ/นิทานใช้ "{kid1}" แล้วแทนค่าบนเซิร์ฟเวอร์)
หน้าความเป็นส่วนตัว (`#/privacy`) เพิ่ม 1 ย่อหน้า; บรรทัดเดียวบนหน้าคำถามบอกว่าส่งอะไร

## 8. ค่าใช้จ่ายและขีดจำกัด

| ขั้น | calls | หมายเหตุ |
|---|---|---|
| โครง | 1 (+1 ต่อการแก้) | Sonnet |
| ร่างเต็ม | ~20–30 | เท่ากับนำเข้า PDF; ข้อความคู่มือไม่มี → input เล็กกว่า |
| แก้หนึ่งวัน | 1–2 | |

ใช้โควตาเดียวกับผู้ช่วยอื่น (`STORY_DAILY`, `aiTake`) — **ปฏิเสธล่วงหน้า** (429 `limit {left, need}`) ถ้าโควตาวันนี้ไม่พอทั้งเล่ม
(เหมือน import) · งานเดียวต่อครั้งต่อครอบครัว (claim ก่อน await แรก) · บันทึก token ลง `ai_usage` → หน้า `#/health` เห็นค่าใช้จ่ายรายเดือน
ประมาณ $0.30–0.80 ต่อเล่ม (Sonnet, ต้องวัดจริงในเฟส 1) — ใช้ตั้งราคาแพ็กเกจภายหลัง

## 9. เทคนิค (สรุปสำหรับคนทำ)

- **Route/หน้า:** `#/planner` (คำถาม), `#/planner/route` (โครง), ใช้ `#/import` เดิมแสดงงาน/ร่าง · views.js `viewPlanner` + `viewPlannerRoute`
- **API:** `POST /api/b/planner/route {answers}` → โครง JSON (ไม่บันทึก, เก็บในเครื่อง `ls('plannerDraft')`)
  · `POST /api/b/planner/draft {answers, route}` → 202 งานเบื้องหลัง (ใช้ job/poll ของ import: `GET /api/b/import`)
  · เฟส 2: `POST /api/b/planner/day/:trip/:day {ask}` → ร่างวันใหม่ · `PUT …/day/:trip/:day {plan}` → ใช้
- **Server:** `server/planner.js` — prompt ของโครง; ร่างเต็ม = `bookimport.run()` แยกส่วนรับ input (`source: 'manual' | 'brief'`)
  ให้ขั้นต่อๆ ไปใช้ร่วมกัน (ไม่ทำท่อที่สอง) · `server/countryfacts.js` ตารางข้อมูลประเทศ
- **Seed:** `putSeed(c, seed, 'planner')` (source ใหม่ แยกจาก `seed`/`manual`) · `trips.kind = 'plan'` · เก็บคำตอบใน `theme.planner` (ไม่มีชื่อเด็ก) ไว้ทำ "แก้วัน"
- **Migration:** ไม่ต้องมี (ใช้ `book_drafts`, `trips.theme` ที่มีอยู่) — ถ้าต้องเก็บประวัติแก้วัน ใช้ `trip_days.plan.prev`
- **ข้อความ:** ไทย/อังกฤษผ่าน `L()`, คำศัพท์ตาม glossary (ผู้ช่วย, เล่ม, เช็ก)

## 10. เฟส

| เฟส | ขอบเขต | ประมาณ |
|---|---|---|
| **1** | คำถาม → โครง (แก้ได้) → ร่างเต็ม → ตรวจ → บันทึก · ตารางข้อมูลประเทศ · ป้าย "เช็กก่อนไป" · push เมื่อเสร็จ · เทสต์ | ใหญ่ที่สุด |
| **2** | แก้ทีละวัน (ฝน/ป่วย/ร้านปิด) + อากาศสด + ย้อนกลับ 1 ครั้ง | กลาง |
| **3** | ค้นเว็บยืนยันร้าน/เวลาเปิด · ร่าง 2 แบบให้เทียบ · ต่อเติมจาก "ไปอีกครั้ง" ของเล่มจากรูป | กลาง |

## 11. เรื่องที่ต้องให้เจ้าของตัดสิน

1. **ค้นเว็บ (เฟส 3):** ยอมให้ส่ง "ชื่อสถานที่ + เมือง" ไปค้นเว็บเพื่อยืนยันข้อมูลไหม (แม่นขึ้นมาก, ค่าใช้จ่ายเพิ่ม ~2–3 เท่า)
2. **โควตา:** ร่างเต็ม 1 เล่มใช้ ~25 calls จาก 60/วัน — ปรับ `STORY_DAILY` หรือแยกโควตาวางแผน (เช่น 3 เล่ม/เดือน/ครอบครัว)?
3. **ชื่อบนจอ:** "วางแผนกับผู้ช่วย" หรือ "ให้ผู้ช่วยวางแผนทริป"?
4. **ประเทศเริ่มต้นของตารางข้อมูลประเทศ:** แนะนำเริ่มจากประเทศที่คลังรูปมีครบ (ไทย ญี่ปุ่น เกาหลี ไต้หวัน ฮ่องกง/มาเก๊า สิงคโปร์ มาเลเซีย เวียดนาม ออสเตรเลีย นิวซีแลนด์ ยุโรปหลัก) — ประเทศอื่นใช้ได้แต่ส่วนฉุกเฉินบอก "เช็กเบอร์ก่อนไป"
