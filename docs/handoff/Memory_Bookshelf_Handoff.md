## 2. เป้าหมายของชั้นหนังสือ (PRD ย่อ)

**ปัญหา:** แอปตอนนี้เป็นของทริปเดียว ผูกกับ Artifact ที่ไปได้หลายทริปแต่ข้อมูลความทรงจำควรอยู่ยาว 10–20 ปี ไม่ควรฝากไว้ที่เดียวกับแอปคู่มือทริป
**เป้าหมาย:** ที่เก็บความทรงจำของเด็ก ๆ ข้ามทริป เปิดดูเป็น "ชั้นหนังสือ" แต่ละทริปคือเล่มหนึ่ง

**User stories (MVP)**
1. ในฐานะพ่อแม่ ฉันเห็นปกทริปทั้งหมดบนชั้น เปิดเล่มไหนก็ได้
2. ฉันเปิดเล่มแล้วเห็นหน้าปก สถิติ ไฮไลต์ ครั้งแรก นิทาน และหน้าตามวัน (เหมือนสมุดในแอป)
3. ฉันเพิ่ม/แก้รูป คำพูดน่ารัก อารมณ์ ของโปรด บันทึกพ่อแม่ ครั้งแรก ได้ทั้งระหว่างทริปและย้อนหลัง
4. ฉันให้ Claude แต่งนิทานจากบันทึก (กดเองเท่านั้น) และเก็บไว้กับเล่ม
5. ฉันดาวน์โหลดเล่มเป็น PDF พร้อมรูป
6. ฉันเชิญคุณพ่อ/คุณแม่/ญาติดู หรือแก้ไข โดยแยกสิทธิ์ได้
7. ฉัน import ข้อมูลจากแอป Harbour Hop เข้ามาเป็นเล่มแรกได้

**ภายหลัง (ไม่ใช่ MVP):** ไทม์ไลน์ข้ามทริป · สถิติสะสม (ประเทศ/เที่ยวบิน/ร้านที่เคยกิน) · "วันนี้เมื่อปีก่อน" · ส่วนสูง/อายุตอนไปแต่ละทริป · พาสปอร์ตสะสมตราประทับ (ต่อจากพาสปอร์ตเด็กที่ทำไว้) · ให้เด็กวาดรูปแล้วแนบ · เสียงอัดคำพูด (ยังไม่เคยตรวจว่าทำได้ในแอป)

## 3. Data model ปัจจุบัน (ต้นทางที่ต้อง import)

### 3.1 คอลเลกชันใน Artifact `db`
| collection | doc id | ความหมาย |
|---|---|---|
| `moments` | ดูข้างล่าง | ความทรงจำทั้งหมด (รูป คำพูด อารมณ์ ฯลฯ) |
| `visits` | `p<d>_<hash>` / `r_<hash>` / `c_<hash>` | เช็กอินที่เที่ยว/ร้านอาหาร `{kind:"p"\|"r"\|"c", en, th, zh, d, at}` |
| `days` | `d0`…`d5` | วันที่กด Done `{done:bool, at}` |
| `checks` | id ของข้อในเช็กลิสต์ | เฉพาะคู่มือทริป ไม่ใช่ความทรงจำ — ไม่ต้อง import |

### 3.2 เอกสารใน `moments` (ทุกเอกสารมี `trip:"hk2026"`, `at` = epoch ms)
| `k` | doc id | ฟิลด์เฉพาะ |
|---|---|---|
| `photo` | `ph<rand>` | `d` (0–5), `img` (asset id 32 hex), `text` (คำอธิบาย), `hi` (ไฮไลต์) |
| `quote` | `q<rand>` | `d`, `who` (`mimi`\|`mika`\|`both`), `text`, `hi` |
| `mood` | `mood_d<d>_<who>` | `d`, `who`, `e` (อีโมจิ) — หนึ่งค่า/วัน/คน |
| `fav` | `fav_d<d>` | `d`, `text` — ของโปรดวันนี้ |
| `note` | `note_d<d>` | `d`, `text` — บันทึกของพ่อแม่ |
| `first` | `first_<key>_<who>` หรือ `first_c<rand>` | `key` (ดู 3.4 หรือ `"custom"`), `who`, `d`, `text` (เฉพาะ custom) |
| `story` | `story_d<d>` / `story_all` | `d` (−1 = ทั้งทริป), `text`, `lang` |

ตัวอย่าง:
```json
{"trip":"hk2026","k":"quote","d":1,"who":"mika","text":"ปลาอยู่ในน้ำเหมือนหนูเลย","hi":false,"at":1796559600000}
{"trip":"hk2026","k":"photo","d":1,"img":"3fa85f64a1b24c0e9d2e7b1c8e4d5a60","text":"ที่ท่าเรือ","hi":true,"at":1796560800000}
```
หมายเหตุ: `at` ของ `visits` ใช้แสดงเวลาเป็นเวลาฮ่องกง (UTC+8) ผ่าน `hkTime()`; ข้อมูล `d` คือ index วัน 0–5 ไม่ใช่วันที่ — วันที่จริงมาจากแผนทริป (5–10 ธ.ค. 2026)

### 3.3 ค่าคงที่ที่ใช้ใน UI
- Kids: `mimi` 👧 มีมี่ (3 ขวบ), `mika` 👶 มีก้า (1 ขวบครึ่ง)
- Moods: 😄 🥰 🤩 😋 😴 😢
- Day gradient/emoji: ✈️ 🏰 🌊 🏮 🐼 🧳 (วัน 1–6)

### 3.4 รายการ "ครั้งแรก" (key · emoji · ไทย · อังกฤษ)
`plane ✈️ นั่งเครื่องบินข้ามประเทศ` · `bridge 🌉 ข้ามสะพานทะเลยาว ฮ่องกง–มาเก๊า` · `ferry 🚢 นั่งเรือข้ามทะเล` · `train 🚆 นั่ง Airport Express / MTR` · `mickey 🐭 เจอมิกกี้เมาส์ตัวจริง` · `sponge 🧽 เจอสพันจ์บ็อบที่ Nickelodeon` · `water 🌊 เล่นสวนน้ำ` · `teamlab ✨ ห้องศิลปะแสงสี teamLab` · `dimsum 🥟 กินติ่มซำ` · `lights 🎄 ดูไฟประดับคริสต์มาส`
→ ในชั้นหนังสือควรทำเป็น **ข้อมูลต่อทริป** (แต่ละทริปมีรายการแนะนำของตัวเอง) ไม่ใช่ค่าคงที่ระดับระบบ

## 4. Schema ที่เสนอสำหรับชั้นหนังสือ (Postgres)

```
families(id, name)
members(id, family_id, email, display_name, role)           -- owner | editor | contributor | viewer
children(id, family_id, name_th, name_en, nickname, birth_year_month)   -- เก็บเดือน/ปีเกิดเท่าที่จำเป็นต่อ "อายุตอนไปทริป"
trips(id, family_id, slug, title, date_from, date_to, cover_media_id, source)   -- source: 'harbour_hop_import' | 'manual'
trip_days(id, trip_id, day_index, date, title, emoji, gradient_from, gradient_to)
entries(id, trip_id, day_id NULL, child_id NULL, kind, text, mood, first_key, highlight bool, occurred_at, created_by, created_at, updated_at)
   -- kind: quote | mood | fav | note | first | story | place   (photo อยู่ที่ media)
media(id, trip_id, day_id NULL, storage_key, mime, bytes, width, height, caption, highlight, taken_at, created_by)
places(id, trip_id, day_id, kind, name_th, name_en, name_zh, visited_at)    -- มาจาก visits
firsts_catalog(id, trip_id, key, emoji, label_th, label_en)
stamps(id, trip_id, awarded_at)                              -- ตราประทับเมื่อทริปเสร็จ
```
Mapping จาก `moments`: `photo`→`media`, `quote/mood/fav/note/first/story`→`entries`, `visits`→`places`, `days`→(ใช้คำนวณ `stamps`).
หลักการ: ทุกตารางข้อมูลของครอบครัวมี `family_id` (หรือ join ถึงได้) ตั้งแต่วันแรก — เผื่อหลายครอบครัว/multi-tenant ภายหลัง แต่ MVP มีครอบครัวเดียว

## 6. Behaviour ที่ต้องคงไว้ (จาก `v2_memory.js`)

- **หนึ่งเอกสารต่อหนึ่งรายการ** (ไม่ใช้เอกสารรวมต่อวัน) เพื่อไม่ให้หลายคนเขียนทับกัน — ในระบบใหม่คือหนึ่งแถว/รายการ; mood/fav/note เป็น upsert ตาม (วัน, เด็ก)
- Draft ของช่องพิมพ์ไม่หายเมื่อมีข้อมูลซิงก์เข้ามา (อย่า re-render ระหว่างกำลังพิมพ์)
- ลบต้องแตะ 2 ครั้ง (ไม่ใช้ `confirm()`)
- ไฮไลต์ ⭐ ที่รูป/คำพูด → ขึ้น "ช่วงเวลาที่ชอบที่สุด" ในสมุด
- ตราประทับ: ได้เมื่อ **ทุกวันของทริปถูกกด Done หรือวันที่ผ่านพ้นวันสุดท้ายของทริปแล้ว** (`tripOver()`); ก่อนหน้านั้นแสดงเป็นเส้นประ
- การอัปโหลดรูป: ย่อเป็น JPEG ด้านยาวสุด 1600 px, คุณภาพ ~0.8, ปรับ orientation, ทีละรูป พร้อมตัวแสดงความคืบหน้า
- ใช้ผ่านมือถือเป็นหลัก (320–375 px) ทั้งโหมดสว่าง/มืด; ภาษาไทย/อังกฤษสลับได้

### กติกานิทาน (คัดลอกหลักการมาใช้ตรง ๆ)
เรียก Claude **เมื่อผู้ใช้กดเท่านั้น** ไม่เรียกอัตโนมัติ; ส่ง **ข้อความเท่านั้น (ไม่ส่งรูป)**; พรอมต์:
> เขียนนิทานก่อนนอนภาษาไทย 120–180 คำ (ทั้งทริป 250–350 คำ) ตัวเอก "มีมี่" (3 ขวบ) และ "มีก้า" (1 ขวบครึ่ง) — ใช้เฉพาะข้อมูลที่ให้ ห้ามแต่งสถานที่/เหตุการณ์/คำพูดเพิ่ม ถ้าข้อมูลน้อยให้เล่าสั้นลง คำง่าย ประโยคสั้น อบอุ่น ใส่คำพูดของเด็กในเรื่อง ปิดด้วยประโยคฝันดี ตอบเฉพาะตัวนิทาน ไม่มีหัวข้อ/markdown

ข้อมูลที่แนบต่อวัน: ชื่อวัน/วันที่, ที่ไป, อารมณ์, คำพูด, คำอธิบายรูป, ของโปรด, บันทึกพ่อแม่, ครั้งแรกของวันนั้น. ล้างสัญลักษณ์ markdown ก่อนบันทึก. ถ้าย้ายไปเรียกจาก server ให้ใช้ Anthropic API โดยเก็บ API key ใน Railway environment variable เท่านั้น

## 7. ความเป็นส่วนตัวและกฎหมาย (สำคัญ — เป็นรูปและข้อมูลของเด็กเล็ก)

- **PDPA:** ข้อมูลเด็ก (ชื่อ รูป ปีเกิด) ต้องเก็บเท่าที่จำเป็น มีวัตถุประสงค์ชัด ลบ/ส่งออกได้ตามคำขอของผู้ปกครอง
- **ไม่มี public URL ของรูป** — ใช้ signed URL อายุสั้น หรือ proxy ผ่าน backend ที่เช็กสิทธิ์; ปิด directory listing; ไม่ให้ search engine เห็น (`noindex`)
- **ลบ EXIF/GPS** ออกจากรูปตอนอัปโหลด (พิกัดบ้านและโรงแรมของเด็กรั่วได้)
- เข้ารหัสระหว่างส่ง (HTTPS) และ at rest ตามที่ผู้ให้บริการรองรับ; สำรองข้อมูล DB + storage เป็นประจำและทดสอบกู้คืนอย่างน้อยหนึ่งครั้งก่อน go-live
- สิทธิ์ 4 ระดับ ให้ตรงกับที่ใช้อยู่ใน Artifact: viewer (ดูอย่างเดียว) · contributor (จดคำพูด/อารมณ์/ครั้งแรกได้ แต่ลงรูปไม่ได้) · editor (ลงรูป แก้ไข) · owner (ลบ/เชิญ) — *ถ้าอยากให้ contributor ลงรูปได้ด้วยให้ถามเจ้าของ*
- ไม่ส่งรูปเด็กให้บริการ AI ใด ๆ เป็นค่าเริ่มต้น
- เจ้าของคือผู้ปกครอง ชื่อบัญชีและอีเมลอยู่ในระบบ auth เท่านั้น ไม่ใส่ในไฟล์ส่งออกสาธารณะ

## 8. ข้อเสนอสถาปัตยกรรมและขั้นตอนงาน (ตามเวิร์กโฟลว์ของเจ้าของ)

เจ้าของใช้ **Railway** เป็น deploy target. บันทึกจากเจ้าของ: GitHub account ถูกจำกัด (authorize แอปภายนอกไม่ได้ → Railway ต่อ GitHub ไม่ติด) และกำลังวางแผนย้าย Git host → **อย่าสมมติว่า GitHub → Railway auto-deploy ใช้ได้**; เตรียมทางเลือก deploy ผ่าน Railway CLI หรือ Git host อื่นไว้ใน ADR

**Phase 1 — ก่อนเขียนโค้ด**
1. **PRD** — ใช้หัวข้อ 2 เป็นฐาน ยืนยันขอบเขต MVP กับเจ้าของ
2. **UX/UI + Design System + Design Token** — คงภาษาภาพของแอปเดิม: gradient รายวัน (`--acc`/`--acc2`), `--sunset`/`--pop`, สีหัวข้อ `--hc0..4`, ฟอนต์ KIRA UI, การ์ดโค้งมน; ดึง token จาก `v2_layer.css` (บล็อกบนสุดและส่วน memories)
3. **ADR** ที่ต้องตัดสิน:
   - Framework (เช่น Next.js/Remix หรือ SPA + API) — *ถ้าเลือก Next.js: ดูกฎ "use-client ratchet" ของ CI ก่อนเพิ่มหน้า (คงจำนวน client page ให้คงที่ / ทำเป็น server component ก่อนถ้าได้)*
   - Database: Postgres บน Railway + ORM/migration tool
   - **ที่เก็บรูป:** ตรวจตัวเลือก storage ที่ Railway มีอยู่ ณ ตอนนั้น (volume / bucket) เทียบกับ S3-compatible ภายนอก; พิจารณาว่า volume ผูกกับ service เดียวและกระทบการ scale/สำรอง
   - Auth: magic link หรือ passkey สำหรับครอบครัวขนาดเล็ก (ไม่ต้องรหัสผ่าน)
   - รูปแบบ real-time (ถ้าต้องการให้คุณพ่อ/คุณแม่เห็นรายการใหม่ทันทีเหมือนในแอป): polling เบา ๆ หรือ SSE
   - ส่งออก PDF: render ฝั่ง server (Playwright/Chromium หรือ WeasyPrint) ใช้ฟอนต์ KIRA UI
4. **Infrastructure & Pipeline** — Git flow, review/merge, CI/CD ไป Railway, environment (dev/prod) และ secrets

**Phase 2 — Coding:** Functional → Non-functional (cache, รูปแบบย่อรูป/thumbnail, logging) → Security (authz ทุก endpoint ตาม `family_id`, ป้องกัน IDOR ของ media, rate limit upload, ตรวจ mime/ขนาด)

**Phase 3 — Testing:** smoke test หลัง deploy · UAT กับเจ้าของ (ลงรูปจริงจากมือถือ iPhone/Android, ใช้เน็ตช้า, โหมดมืด)

**กฎการส่งงาน (เจ้าของกำหนดไว้)**
- ทำเสร็จ → รัน test → commit → เปิด PR → รอ CI เขียวทั้งหมด → squash-merge → deploy (**merge เมื่อผ่านทุก check เท่านั้น**)
- สร้าง migration ใหม่: ดูเลข migration ล่าสุดบน `main` ก่อนเสมอ (PR ขนานมักชนเลข); ถ้าชนใช้ union/rebase กับไฟล์ triage และ journal; เฝ้า check `migrations-journaled`
- แก้ไฟล์ด้วย Edit/Write เท่านั้น (ห้าม heredoc/PowerShell Set-Content ที่ทำ UTF-8 พัง) และตรวจว่าข้อความไทยลงไฟล์จริง
- หน้า dashboard/รายงาน: ตรวจขนาดตัวอักษร/รูปบนจอ PC กว้างด้วย `preview_eval` ก่อนปิดงาน และใช้ grid แบบ auto-fill

**การใช้งานนอกประเทศ:** ทริปมักไม่มีเน็ตเสถียร → PWA, อัปโหลดแบบ queue/retry ได้, แสดงรูปย่อก่อน, และไม่ทำให้ข้อความที่พิมพ์ค้างหายเมื่อซิงก์

## 9. คำถามที่ต้องถามเจ้าของก่อนลงมือ

1. ใครอยู่ในครอบครัวที่ต้องเข้าถึงได้ (กี่คน ใช้อีเมลอะไร ใครลงรูปได้)

5. งบประมาณรายเดือนที่รับได้ (Railway + storage) — ใช้เลือก volume/bucket/S3
6. ภาษาของระบบ: ไทยเป็นหลัก สลับ EN ได้เหมือนแอปเดิมใช่ไหม
7. ต้องการสมุดแบบพิมพ์ (โฟโต้บุ๊ก) ขนาดไหน ใช้ PDF เดียวกับที่ส่งออกหรือแยกเลย์เอาต์
8. กำหนดเวลา: ต้องใช้งานก่อน 5 ธ.ค. 2026 หรือหลังกลับจากทริป
