# CLAUDE.md — Memory Bookshelf

Shown to users as **MM Memory** (tab title, home-screen name, login page, top bar, push fallback title, PDF footer and back cover); the code, docs and backup format keep the project name Memory Bookshelf (`memory-bookshelf-backup` must not change — old backups must still restore).

Family memory bookshelf for Mimi (มีมี่) and Mika (มีก้า): one book per trip. Self-hosted on **Railway**: Node 22 + **Postgres** + photos in a **Railway Storage Bucket**. The owner (Oshinei) writes Thai and wants direct execution, concise replies. UI strings are bilingual (TH/EN) through `L(th, en)`.

Read first: `docs/PRD.md` (scope, approved) · `docs/ADR.md` (stack decisions) · `docs/DESIGN.md` (look = the owner's Trip Operations Manuals) · `docs/handoff/ACCEPTANCE.md` (acceptance criteria). `README.md` is the Thai deploy/usage doc.

## Architecture (no build step, no framework)
- `server/index.js` Express: login/viewer link, `/healthz` (Postgres only — Railway's deploy health check, so a bucket outage can't block a deploy; `?full=1` adds photo storage, read by the Uptime workflow; `server/health.js`), bookshelf router, backup/import, static + SPA fallback. Refuses to boot without `DATABASE_URL`.
- `server/bookshelf.js` the API (`/api/b/*`, `/media/:id(/t)`) + `syncSeeds()`. Everything is scoped by `family_id` (one family in MVP). Writes are idempotent upserts with client ids (offline queue retries safely). mood/fav/note use deterministic ids (`<trip>.mood.d<day>.<kid>`). Table `spend` (`PUT/DELETE /api/b/spend/:id`: amount, ISO currency, category food/transport/tickets/stay/shop/other, note) = what we actually spent, typed on the record page (`spendBlock`; the food category offers the day's places from `spendPlaces` → `eatForDay`: plan picks, on the route, near the bed, the rest); it is in backups and the state, never in a seed or the printed book. Dark mode: `--paper #1B2230` family (lifted from near-black so cards and text read); the kids' passport covers are `.ppc.kid-<slug>` (rose / sky, soft), the generic cover sunny. `POST /api/logout` has its button at the foot of the shelf (clears the cookie and the phone's offline copy).
- `server/seeds/*.json` trips bundled with the app, in `docs/handoff/trip.schema.json` format + `theme` (DESIGN.md tokens) + per-day plan keys (→ `trip_days.plan`: timeline, moving, pick, planB, money, tips, stay, route, eat, learn, quiz, tale = the guide's story of the day `{th, en, scenes:[{e, h, th, en}]}`, a picture-book card read scene by scene by kid.js `sayTale`) + `info` (→ `trips.info` pocket guide) + `passport`. Synced on every boot; "Done" marks and app-made trips are kept. AU content was imported from the owner's *The Big Hop* artifact; a test asserts no booking refs/confirmation numbers/costs reach the state.
- `server/migrate.js` + `migrations/NNNN_*.sql` + `migrations/journal.json`: run on boot under an advisory lock; an edited applied migration is refused.
- `server/storage.js` bucket (`BUCKET`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`, `REGION`, `ENDPOINT`) or local disk. Objects `p/<trip>/<id>.jpg` + `t/…` are never public.
- Voice memos share the `media` table: `PUT /api/b/media/:id?kind=audio` keeps the clip as the phone recorded it (webm-opus / mp4-aac, ≤ 8 MB, `AUDIO_EXT`) under `a/<trip>/<id>.<ext>`, `mime` set, no thumbnail; `/media/:id` serves audio with byte ranges (Safari needs 206); backups carry them as `audio/<id>.<ext>`. Client: `isAudio`/`audioOf` vs `mediaOf` (photos only, so counts, print and share never see a clip); recorder in `clipsBlock` (`startRec`/`addClip`, 30 s cap, queued like a photo), clips play in the book day card (`noprint`) and in kid mode (`kidAudio` → `kidplay`).
- `server/images.js` sharp: EXIF-rotate, strip all metadata/GPS, 2560 px + 520 px thumb. `server/backup.js` complete zip + idempotent restore (archiver 8 is ESM-only: `const { ZipArchive } = require('archiver')` relies on Node ≥ 22.12 require(esm); the CI docker job builds a zip inside the image). `server/auth.js` family code → HMAC cookie `mb` (editor); relatives' view-only PIN `VIEW_PIN` (same pad, must differ from `FAMILY_CODE`) or link `/v/<VIEW_TOKEN>` → viewer (sees every book); **relatives in groups** (`#/viewers`, editors, `viewViewers`; table `viewer_groups`, migration 0012, not in backups): each group its own PIN (6–12 digits, stored only as `A.pinHash` = HMAC with the session secret) and/or link `/v/<random token>`, and the books ticked for it — the cookie carries the group id (6th token part), `attachUser` looks the group up (15 s cache, cleared on edit) and `A.canSee(user, trip)` scopes state, seed, media, PDF, weather and hearts; deleting a group signs its phones out, a new link kills the old (test/viewers.mjs); secret from `SESSION_SECRET` or Postgres `settings`.
- `server/story.js` bedtime stories via `@anthropic-ai/sdk` (`STORY_MODEL`, default `claude-sonnet-5-5`; `fallbacks: "default"` opted in): only on button press, text facts only (never photos), streamed to the page as SSE by `POST /api/b/story`; disconnect = abort upstream, nothing saved; at most `STORY_DAILY` (default 60) model calls per UTC day, then 429 `limit`. Same endpoint with `mode: 'sum'` = the day in a few lines (entry kind `sum`, id `<trip>.sum.d<i>`, migration 0009): streamed into the record page's `#sumtext` box (`sumBlock`), saved, editable (blur-save upserts the same id), leads the book's day page (`.daysum`) and the PDF; shares the daily cap. `mode: 'msg'` = a note for the relatives (`msgBlock`): streamed into `#msgtext`, **never saved** (kept only as the box's draft), sent by the parents through the phone's share sheet (`share` with `data-src="msg"`, + up to 3 photos from the phone; desktop copies). **Ask the guide** (`POST /api/b/ask`, editors, `askBlock` on the Today glance page + suggestion chips): `server/guide.js` cuts the book's seed guide text (trips.info + day plans, one language) into chunks and sends the overview + the chunks sharing the most character pairs with the question (≤ 16k chars; Thai-safe) — never the family's records or photos; the answer streams back, is never saved (`askAns` keeps it on the page); shares the daily cap. **Both languages** (`POST /api/b/translate {trip, day}`, `trBlock` on the record page): the day's untranslated quote/note/fav/sum/custom-first texts go to Claude in one call (Thai → en, else → th, JSON back) and each translation is saved in `entries.tr` (migration 0010) — kept while the text is unchanged, cleared by the upsert when it changes; `trLine(e)` shows it under the text in the book, the words page and the PDF. `mode: 'talk'` = three bedtime questions about the day (entry kind `talk`, id `<trip>.talk.d<i>`, one per line, migration 0011; `talkBlock` on the record page) → kid mode tile 💬 `talk` (`kidTalk`): question cards, a tap reads one aloud in its own language (`kidtalk`). Usage: table `ai_usage` (migration 0013, per family per UTC day: calls, tokens in/cached/out) — the daily cap is taken atomically there (`aiTake`, survives redeploys) and story.js `onUsage` adds each finished call's tokens; `GET /api/b/ai` (editors) → the shelf's ✨ Claude card (`aiCard`) and "Claude today n/60" on the record page (`aiToday`); optional USD estimate only when `AI_USD_PER_MTOK_IN`/`_OUT` are set. Ask-the-guide sends the stable part (overview + the asking day's plan, ≤ 8k chars, `guide.excerpt().stable`) first with `cache_control: ephemeral`, the matched chunks + question after. Offline (or the network drops mid-question) the ask box answers from the manual on the phone instead: `askOffline` strips filler words (`ASK_FILL_TH/EN`) and runs the book search (`bookFind`), showing the top sections as links — no Claude. **Tonight, Claude helps** (record page, editors, `aiGroup` in views.js): the recording comes first; every Claude block of the day sits together after it under one panel `#aipanel` (`aiPanel`): a grid of steps (`aiSteps`: photos · summary · both languages · story · questions · morning game · note for family, each with its status, `jump` to its box) and **do it all** (`aiall` in sheets.js: `aiTodo` = photos → sum → story → talk not yet done, one Claude call each via `A.photoai`/`A.story`, which return truthy when Claude finished (`A.photoai` returns the answer, so the photos go round in calls of 12 until `left` is 0, at most 10 rounds; the button's count is `aiCalls`); stops on the first failure or `aistop`; progress in `aiRun`). What travels to Claude is said once, behind the panel's ⓘ (`aiNote`); each block keeps a one-line note. `.aijump` under the day strip jumps down to the panel ("n to do"). The 21:30 record-the-day push opens `/log/<i>/ai`, which scrolls to `#aipanel` once per arrival (`aiOpened`); `main .blk` has `scroll-margin-top` so jumps land below the top bar. Trip spending summary `#/t/<trip>/spend` (`viewSpend`, editors; tile on the menu): per currency (never converted) by category with bars, day by day, the biggest items. `mode: 'letter'` (whole trip, `day: null`) = a letter from the parents to the kids for when they are older (entry kind `letter`, id `<trip>.letter.all`, migration 0014, trip-wide; `letterBlock` on the book page: editable textarea, blur saves; read-only for relatives; the PDF's last page before the back cover `.letterp`). **What our family likes** (`POST /api/b/likes`, editors; `likesBlock` at the top of the travel notebook): every trip's reviews (names, stars, tags, the kids' verdicts, notes) → Claude → saved in `settings.family_likes` for both parents (`GET /api/b/likes`, editors only — it names places from every trip, so not for relatives' groups). Tests use a local mock via `ANTHROPIC_BASE_URL`.
- More Claude modes on `POST /api/b/story` (same cap, text facts only): `next` = tomorrow in five lines (`nextBlock` on the Today page, editors, not on the last day; facts = `nextFacts`: tomorrow's timeline, stay, planB/moving/money/tips, the climate note, the live forecast via weather.js, then how today went) — streamed, **never saved** (`nextAns`); `mquiz` = the morning memory game (`mquizBlock` on the record page; JSON prompt without the NATURAL tail, `story.parseQuiz` keeps 2–4 picture answers per question and shuffles them; saved as kind `mquiz`, id `<trip>.mquiz.d<i>`, migration 0015) → kid mode tile 🧠 `memory` on the next day (`memQuiz(t, i-1)`, one question at a time, a wrong tap says "try again", no score); `fore` = the book's foreword (whole trip, kind `fore`, id `<trip>.fore.all`; `foreBlock` near the top of the book page, blur-saves; the PDF's first page after the cover `.forep`).
- **Look at today's photos** (`POST /api/b/photos/ai {trip, day, lang, all?}`, editors, only when `story.photoEnabled()` = key + `PHOTO_AI=1`; `features.photoAi` in the state): the day's photos with `media.ai_at IS NULL` (≤ 12 a call, `all` resends the day) go as 520 px thumbnails (`keyThumb`, never the full file) with the day's title and stop names (planned + check-ins + the stay) → `story.describePhotos` (JSON per id) → `media.caption` only where the parents wrote none, `media.tags` (keys from `story.TAGS` = core.js `PHOTO_TAGS`, bilingual labels via `tagLabel`), `media.place` (one of the given stop names or ''), `ai_at` (migration 0016; all three in backups and the state, `ai: true/false`); Claude's `best` picks (≤ 2, never a drawing) get `highlight` only while the day has no ⭐ yet — the parents' stars win (`starred` in the answer). Shares the daily cap; "Photos" is the first step of tonight's panel on a day with photos, so the captions feed the summary and the story. Client: `photoAiBlock` under the record page's photo box (`photoai`), the lightbox edits tags (`#lbtags`, comma-separated, ≤ 10) and place (`#lbplace`) → `PATCH /api/b/media/:id {tags, place}`; the book's day page groups photos by stop (`mosaicByPlace`, `.phgrp`); `#/t/<trip>/photos` (`viewPhotos`, tile on the menu) = every photo by tag, chips filter in place (`phtag`), grouped day → stop. The book search (`#/t/<trip>/search`) also finds photos (`photoFind`: caption, place, tag key and its Thai/English name, with the search's synonyms) — a `.sphotos` mosaic above the text results (first 12), opening the photo viewer.
- On this day (push `extras()`): after a trip, each day's anniversary at 09:00 home time (`ANN_AT`, up to 20 years) — "📅 วันนี้เมื่อ n ปีก่อน", opens `/book/d/<i>`, sent only when that day has memories (`need`); `tick()` also loads past trips.
- Today's bag (`bagBlock`/`dayBag` in views.js, Today glance page, editors): fixed list `BAG` of `[key, emoji, th, en, regex]`, each shown when its regex matches the English of one of the day's timeline rows or `wx` (reason = that row's time + text), plus `BAG_ALWAYS` (snacks, nappies, spare clothes); ticks are per phone (`data-ck` `<trip>.bag.d<i>.<key>` in `ls('ck')`), nothing saved on the server.
- Photos on Wi-Fi only (`upBlock` on the record page and `/offline`; core.js `holdMedia`/`heldCount`/`upNow`): with `ls('wifionly')` the queue's blob ops (photos, clips, drawings) — and later ops on the same media id (⭐, caption, delete), kept in order — wait while `navigator.connection.type === 'cellular'`; where the type is unknown (iPhone, desktop) they wait until "send now" (`upnow`, for this visit). Words always go at once. `allHeld` keeps the 30 s refresh running while only held items remain. `.upw` is redrawn in place by `renderProgress` (never a re-render over a focused field).

Shared via the share sheet / downloaded, preview `#lcprev`.

No rate → it asks, never guesses.
- Home-screen icon shortcuts (manifest `shortcuts`, Android Chrome; iOS has none): `#/go/photo|rec|quote|today` → `curTrip()` → today's record page (`goShortcut` scrolls to and lights `.golit` the box; quote gets the cursor — camera/mic still need a tap) or, for relatives / `today`, the Today page.
- Little one's edition (seed `passport.little`: `kids`, `note`, `days[i]` = 3 point/touch/sound missions, `words`, `cert`; HK and AU: Mika): views.js `littleOf`/`daySpots`/`kidLists`/`littleGot` — missions tick `little.d<i>.<k>` instead of `spot.d…`, no quiz, no `said`/certificate lists, no customs form; a "new words" page (`#lwords`, action `littleword` → a quote for that child on today's day); its own certificate wording (`certText`); kid mode: 👉 "Point it" tile, no words/quiz tiles; stickers, trophies and the story's facts read the same keys.

- Kid home tiles never repeat the kid bar (map, stickers, trophies live only on `.kidbar`); counting (`newCount(t, kid)`) draws mostly today's mission emojis (`daySpots`), then the trip's animals and friends.
- Kid mode on a trip day (`dayNow(t) === i`): a morning **surprise box** banner (`.kidgift` → view `gift`, action `kidgift` → tick `gift.d<i>`, a sticker of its own `giftE(i)` in `stickerSet`, then today's `daySpots` and a go-find button) until opened; from 17:00 trip time (core.js `hourIn`) a **stamp before bed** banner (`.kidnight` → the `stamp` view, which says "ปั๊ก!") until `stamp.d<i>` is ticked.

- Nightly backup during a trip: `GET /api/backup/due` (Bearer `BACKUP_TOKEN`, answers only `{due}`: a trip from the day before it starts to two days after it ends) — the Backup workflow's nightly cron (16:23 UTC) asks first and keeps those 30 days; the weekly run keeps 90.
- `test/offline.mjs` (own group): a real no-signal day — stores the book, **stops the server**, opens every topic page, passport, kid mode and ask-the-guide from the phone, records quote/photo/a real voice clip (Chromium fake mic)/spend, restarts the server and checks everything arrived once; then the Wi-Fi-only switch.
- `server/weather.js` live forecast for the Today page: `GET /api/b/wx/:trip` asks Open-Meteo (free, no key) once per stay with the seed's town-level `stay.ll` and the book's timezone — never the phone's location or anything about the family; only when the trip is within `WX_HORIZON_DAYS` (16), cached 3 h, fails soft to `null`. The client (`ensureWx`/`wxLine` in core.js) fetches once an hour, keeps the answer in localStorage, and draws `.wxlive` under the manual's climate note. Tests mock it via `WX_BASE_URL`.
- `server/pdf.js` A4 PDF: headless Chromium (Playwright shell installed in the image) prints the app's memory-book route `#/print/<trip>` (views.js `viewPrint`: cover · numbers+map · contents · day pages · firsts · words · passport spread per child · hearts · story · notes · back) with a read-only session; one render at a time. `GET /api/b/pdf/:trip`.
- **New book workflow** (owner's rule): the owner plans a trip in any session and sends the artifact link (or the Trip Operations Manual PDF); Claude Code transcribes it to `plan.json` (`docs/handoff/plan.schema.json`, sample `plan.sample.json`) and runs `npm run plan-to-seed -- plan.json` → `server/seeds/<slug>.json` with every default filled and a privacy scan that refuses booking refs/costs/e-mails (`docs/PLAN-TO-BOOK.md`; field details in `docs/NEW-BOOK.md`; `npm run new-book -- …` still scaffolds an empty seed; `plan-to-seed --check <seed>` runs on every shipped seed in the tests). Seeds carry `format: 2`; format changes never rewrite older books — the renderer stays backward compatible.
- **A book from a PDF inside the app** (`#/import`, editors, only with `ANTHROPIC_API_KEY`; `server/bookimport.js`, the engine of `npm run import-pdf` too): `POST /api/b/import?slug=` (raw PDF ≤ 25 MB, one job at a time, 202 → poll `GET /api/b/import`) → `pdftotext` (poppler-utils in the image), the PDF deleted at once → **redaction on the server before anything leaves** (lines with e-tickets / PNR / booking numbers / passport / birth / policy dropped; long numbers, e-mails, baht amounts, blank fields masked) → `IMPORT_EXTRACT_MODEL` (default claude-haiku-5-5) writes days, pocket guide and restaurants in English with the redacted manual as one cached system block → restaurants come in two passes so a 200-place guide arrives complete (every name by area, then rows 40 at a time, one retry for misses) → `IMPORT_WRITE_MODEL` (default `STORY_MODEL`) writes the kids' pages bilingually, then one **extras** call (animals & friends `info.wild` + `wildLabel`, the trip's own `firsts`, `passport.words` with `speak`, the `food` tasting card, the living `map` with clamped x/y and per-day stops, each stay's "why we chose it" via `plan.staysWhy`) and translates every remaining English string (only the Thai comes back, batches of 350) → `scripts/lib/plan-to-seed-core.mjs` (shared with the CLI: validate · toSeed `{art:false}` = no drawn art, colours + `GENERIC_GUIDES` stand in · privacy scan · sanity) → a row in `book_drafts` (migration 0017, not in backups) with report + cost estimate. Each model call takes one of the day's `STORY_DAILY` and adds to `ai_usage`. `GET /api/b/import` lists drafts with a `peek` (cover, dates, table of contents, counts of stops / restaurants / missions / animals / firsts / words / tastes / map stops) and never the seed; the page leads with the running job (progress bar, elapsed time, the step in hand) and shows each draft as a cover with its contents and a per-step cost table; **save** (`POST /api/b/import/:id/save`) runs `putSeed(c, seed, 'manual')` — the same upsert `syncSeeds` uses for bundled seeds (source `seed`), which never overwrites an app-made book and vice versa (`{code:'exists'}`). Text only: the PDF file and its images never reach Claude. Tests: test/story.mjs (a hand-built PDF whose invented reference-looking lines must never reach the mock).
- **Many families** (docs/ADR.md ADR-11): one family = one Railway project (own App service from this repo, own Postgres, own Bucket, own domain and codes) — never one database for several families. `scripts/provision.mjs <family>` creates one with Railway's public GraphQL API (projectCreate → Postgres image service + volume → App from the repo → variableCollectionUpsert with fresh random secrets and `DATABASE_URL=…${{Postgres.RAILWAY_PRIVATE_DOMAIN}}…` → healthcheck/region → serviceDomainCreate → first deploy), prints the codes once, appends `{name, url, token}` to `families.json` (gitignored, on the owner's machine only); the Bucket is two dashboard clicks (no API yet). `scripts/fleet.mjs check|backup` reads that registry; the Uptime workflow takes `MB_URLS` (one `name=url` per line). test/provision.mjs runs the script against a mock API (infra group).
- `server/importer.js` + `scripts/import-harbour-hop.mjs`: Harbour Hop app export → bookshelf (dry run by default, idempotent via `external_id`).
- `server/push.js` trip reminders (Web Push, `web-push`): a grown-up's phone switches them on from the Today page (`remindBar`, actions `remind`/`remindtest`; editors only); a 1-minute tick sends "08:00 · in 30 min — <the step>" 30 min before every timeline row with `t` HH:MM (`trip_days.plan.plan`), in the trip's timezone or the row's own `tz` (departure-day Bangkok rows); plus three fixed-time nudges (`extras()`): store-the-book 19:00 two days before the flight (opens `/offline`) and a countdown door 08:00 each of the last N mornings — both in **home time** (`HOME_TZ`, default Asia/Bangkok: the family is still at home; owner's ask) — (N = `passport.countdown.doors`), record-the-day 21:30 each trip evening (trip timezone) (skipped when the day already has entries/photos); plus a relative's heart (bookshelf `hooks.heart` → `REMIND.heart`): a viewer's heart nudges the grown-ups' phones "ญาติส่งหัวใจมาให้เด็กๆ 💗" (no names, no heart text; opens `/hearts`), at most one per 10 minutes (key `heart.<10-min bucket>`); `push_sent` claims each reminder once; 404/410 drops the phone. VAPID keys from env or Postgres `settings`. Only the plan's words travel — never photos/names. Tables `push_subs`/`push_sent` are not in backups (phones re-subscribe). iPhone: only from the Home-Screen app (iOS 16.4+).
- Graceful shutdown on SIGTERM (Railway redeploys): close server, Chromium, pool.
- `public/` vanilla-JS PWA, classic scripts sharing one global scope: `core.js` (state, `api()`, IndexedDB op queue + optimistic `applyLocal`, helpers) → `views.js` (render functions return HTML) → `sheets.js` (actions `A`, photos, lightbox, sheets, boot) → `kid.js` (kid mode, colouring, finger drawing, sounds, read-aloud, bedtime story player, countdown doors, stickers, living map). `app.css` = DESIGN.md tokens; each book sets its theme on `<html>`. `sw.js` (bump `mbs-vN` when shell files change — the server also stamps `V` with a hash of `public/` (`mbs-vN-<hash>`), so a forgotten bump can't strand phones; its `ART` list must name every file under `public/art` — test/infra.mjs checks; shell **cache-first** from the version's cache (one consistent set per install), art/media/fonts cache-first). Data: the app loads `/api/b/state?lite=1` (no guide text; each trip carries a `seed` hash) with `If-None-Match` → 304 when unchanged; guide text (info, passport, day plans) comes from `/api/b/seed/<trip>/<hash>` once and is reused while the hash holds (`withSeeds`); boot renders the IndexedDB copy first, then syncs. Offline copy of the state lives in IndexedDB `kv` (core.js `idb.get/set`); "Keep this book on the phone" (`packOffline`) warms the SW cache with a book's thumbnails, favourites and art.

## Conventions and rules (from the owner — keep)
- Use the Edit/Write tools for file changes; never shell heredocs / `Set-Content` for Thai text (mangles UTF-8). Verify the edit landed (OneDrive swap races).
- Flow for every change: implement → `npm test` → commit → PR → wait for **green CI** (test, docker, migrations-journaled) → squash-merge → Railway (connected to this repo) deploys `main` by itself; check `/sw.js` shows the new `mbs-vN`. Never merge on red CI. (The GitHub "Deploy" workflow is a manual fallback only.)
- New migration: check the latest number on `main` first (parallel PRs collide); on conflict keep both journal entries (union) and renumber yours. Never edit a migration that is on `main`.
- Look: follow `docs/DESIGN.md` (the manuals). Fonts: **KIRA UI** for all UI/print; Cormorant Garamond only as the HK display face. Verify on a wide desktop and a phone; auto-fill grids, no horizontal overflow at 320/390 px.
- Children's photos: nothing public, no analytics/third-party scripts, no GPS/EXIF kept, no logging of cookies/codes/tokens. Photos never go to an AI **unless the owner sets `PHOTO_AI=1`** (owner's ask, Nov 2026): then only the 520 px thumbnails of one day, only on the "look at today's photos" press, never on upload or by a schedule; every other Claude feature stays text-only. No booking numbers / passports in seeds.
- Never re-render over a focused field (`safeRender`) — a late render swaps the box and loses typed text (this bug happened; see `enqueue`).
- Stable keys: planned-place `key`s in seeds are check-in keys; never rename one for a trip that has started — add a new stop instead.

## Gotchas
- Cloud sessions: `.claude/hooks/session-start.sh` runs **async** (npm install, Postgres :5432, s3rver :4569, `TEST_*` env). Before the first `npm test`, wait for it: `until [ -f /tmp/mb-session-ready ]; do sleep 1; done`.
- Don't `pkill -f`/grep-kill node servers in a shell that runs tests — kill by PID.
- `FAMILY_CODE` unset ⇒ nobody can log in (server only warns).
- Headless Chromium reports `en-US`, so tests see the English UI unless they toggle.
- Docker Hub `minio/minio` is not pullable here; tests use `s3rver` (devDependency) as the S3 emulator.
- Seeds use a mixed hand layout (pretty objects, one-line rows): edit them surgically (replace only the changed lines/keys, then `assert json.loads(new) == expected`) — `json.dump` of the whole file rewrites ~30k lines.
- Escape first, decorate never: a regex run over `esc()` output matches inside entities (`Cook's` → `&#39;` → "39" got highlighted). Match the raw text, escape each piece.
- `.pocket h5` (and other page-level rules) set `--display`, which is serif in HK — a component's own heading rule needs enough specificity (`.tale .scenes h5`).
- Kid mode opens the next trip (HK before AU): to check another book's colouring pages, render `lineArt()` on its SVGs directly.
- Tests: closed `<details>` hide their text from `innerText` — use `textContent`. Headless `speechSynthesis` exists but has no voices; assert the UI state, not the sound.
- A test that needs content not yet written: `git stash` it rather than pushing a red commit.

## Debug mantra
1. **Reproduce before you fix** — see the bug on the real screen (screenshot 390 px + 1440 px, TH + EN), not just in a test.
2. **Read the data, then the code** — most "UI bugs" here were seed data (old manual, wrong key, format drift).
3. **Trust the manual, prove the fact** — every seed fact traces to the manual or the seed; grep before you ship a new one.
4. **One cause, one fix, one test** — write the test that would have caught it (it must fail on the old code).
5. **Look at both books** — HK and AU differ in theme, fonts and guides; a fix for one is checked on the other.
6. **Green CI or it didn't happen** — then check `/sw.js` on the live site and look at the live page.
