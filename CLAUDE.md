# CLAUDE.md — Memory Bookshelf

Shown to users as **LifeBook** (the product name, Nov 2026: tab title, home-screen name, login page, top bar, push fallback title, PDF footer and back cover; a family may rename its own app in `#/family`, the kicker names the children); the code, docs and backup format keep the project name Memory Bookshelf (`memory-bookshelf-backup` must not change — old backups must still restore).

Family memory bookshelf for Mimi (มีมี่) and Mika (มีก้า): one book per trip. Self-hosted on **Railway**: Node 22 + **Postgres** + photos in a **Railway Storage Bucket**. The owner (Oshinei) writes Thai and wants direct execution, concise replies. UI strings are bilingual (TH/EN) through `L(th, en)`.

Read first: `docs/PRD.md` (scope, approved) · `docs/ADR.md` (stack decisions) · `docs/DESIGN.md` (look = the owner's Trip Operations Manuals) · `docs/handoff/ACCEPTANCE.md` (acceptance criteria). `README.md` is the Thai deploy/usage doc.

## Architecture (no build step, no framework)
- `server/index.js` Express: login/viewer link, `/healthz` (Postgres only — Railway's deploy health check, so a bucket outage can't block a deploy; `?full=1` adds photo storage, read by the Uptime workflow; `server/health.js`), bookshelf router, backup/import, static + SPA fallback. Refuses to boot without `DATABASE_URL`.
- `server/bookshelf.js` the API (`/api/b/*`, `/media/:id(/t)`) + `syncSeeds()`. Everything is scoped by `family_id` (one family in MVP). Writes are idempotent upserts with client ids (offline queue retries safely). mood/fav/note use deterministic ids (`<trip>.mood.d<day>.<kid>`). Table `spend` (`PUT/DELETE /api/b/spend/:id`: amount, ISO currency, category food/transport/tickets/stay/shop/other, note) = what we actually spent, typed on the record page (the parents' own ledger: the state sends it to editors only, never to a relative) (`spendBlock`; the food category offers the day's places from `spendPlaces` → `eatForDay`: plan picks, on the route, near the bed, the rest); it is in backups and the state, never in a seed or the printed book. Dark mode: `--paper #1B2230` family (lifted from near-black so cards and text read); the kids' passport covers are `.ppc.kid-<slug>` (rose / sky, soft), the generic cover sunny. `POST /api/logout` has its button at the foot of the shelf (clears the cookie and the phone's offline copy).
- `server/seeds/*.json` trips bundled with the app, in `docs/handoff/trip.schema.json` format + `theme` (DESIGN.md tokens) + per-day plan keys (→ `trip_days.plan`: timeline, moving, pick, planB, money, tips, stay, route, eat, learn, quiz, tale = the guide's story of the day `{th, en, scenes:[{e, h, th, en}]}`, a picture-book card read scene by scene by kid.js `sayTale`) + `info` (→ `trips.info` pocket guide) + `passport`. Synced on every boot; "Done" marks and app-made trips are kept. AU content was imported from the owner's *The Big Hop* artifact; a test asserts no booking refs/confirmation numbers/costs reach the state.
- `server/migrate.js` + `migrations/NNNN_*.sql` + `migrations/journal.json`: run on boot under an advisory lock; an edited applied migration is refused.
- `server/storage.js` bucket (`BUCKET`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`, `REGION`, `ENDPOINT`) or local disk. Objects `p/<trip>/<id>.jpg` + `t/…` are never public.
- Voice memos share the `media` table: `PUT /api/b/media/:id?kind=audio` keeps the clip as the phone recorded it (webm-opus / mp4-aac, ≤ 8 MB, `AUDIO_EXT`) under `a/<trip>/<id>.<ext>`, `mime` set, no thumbnail; `/media/:id` serves audio with byte ranges (Safari needs 206); backups carry them as `audio/<id>.<ext>`. Client: `isAudio`/`audioOf` vs `mediaOf` (photos only, so counts, print and share never see a clip); recorder in `clipsBlock` (`startRec`/`addClip`, 30 s cap, queued like a photo), clips play in the book day card (`noprint`) and in kid mode (`kidAudio` → `kidplay`).
- `server/images.js` sharp: EXIF-rotate, strip all metadata/GPS, 2560 px + 520 px thumb. `server/backup.js` complete zip + idempotent restore (one object in flight at a time — `add` waits for archiver's `entry` event, else a slow download holds every photo in memory; a failed read ends the download instead of hanging it; the zip carries `profile` = the family's app name/kicker/tiles, restored where none was set; `children` rows the seeds made first get their blank birth month, look and drawn characters back through a conditional upsert, so a second restore is still a no-op) (archiver 8 is ESM-only: `const { ZipArchive } = require('archiver')` relies on Node ≥ 22.12 require(esm); the CI docker job builds a zip inside the image). `server/auth.js` family code → HMAC cookie `mb` (editor); relatives' view-only PIN `VIEW_PIN` (same pad, must differ from `FAMILY_CODE`) or link `/v/<VIEW_TOKEN>` → viewer (sees every book); **relatives in groups** (`#/viewers`, editors, `viewViewers`; table `viewer_groups`, migration 0012, not in backups): each group its own PIN (6–12 digits, stored only as `A.pinHash` = HMAC with the session secret) and/or link `/v/<random token>`, and the books ticked for it — the cookie carries the group id (6th token part), `attachUser` looks the group up (15 s cache, cleared on edit) and `A.canSee(user, trip)` scopes state, seed, media, PDF, weather and hearts; deleting a group signs its phones out, a new link kills the old (test/viewers.mjs); secret from `SESSION_SECRET` or Postgres `settings`. **The sign-in pad opens by itself at the last digit**: `/api/brand` carries `pin: {lens, open}` = the lengths a code can have (`FAMILY_CODE`, `VIEW_PIN`, each group's `viewer_groups.pin_len`, migration 0021 — never a digit); sheets.js `pinAuto` submits when the typed length is one of them and no longer one exists (`open` = a group PIN of unknown length, saved before 0021 → the button stays). The page asks *who* first (chips above the code) and fits a 390×664 iPhone screen. **Reminders are offered right after sign-in** (`remindAsk` at the top of the shelf, editors, until on or "later" → `ls('remindLater')`; on an iPhone in Safari it says the Home Screen step first).
- `server/story.js` bedtime stories via `@anthropic-ai/sdk` (`STORY_MODEL`, default `claude-sonnet-5-5`; `fallbacks: "default"` opted in): only on button press, text facts only (never photos), streamed to the page as SSE by `POST /api/b/story`; disconnect = abort upstream, nothing saved; at most `STORY_DAILY` (default 60) model calls per UTC day, then 429 `limit`. Same endpoint with `mode: 'sum'` = the day in a few lines (entry kind `sum`, id `<trip>.sum.d<i>`, migration 0009): streamed into the record page's `#sumtext` box (`sumBlock`), saved, editable (blur-save upserts the same id), leads the book's day page (`.daysum`) and the PDF; shares the daily cap. `mode: 'msg'` = a note for the relatives (`msgBlock`): streamed into `#msgtext`, **never saved** (kept only as the box's draft), sent by the parents through the phone's share sheet (`share` with `data-src="msg"`, + up to 3 photos from the phone; desktop copies). **Ask the guide** (`POST /api/b/ask`, editors, `askBlock` on the Today glance page + suggestion chips): `server/guide.js` cuts the book's seed guide text (trips.info + day plans, one language) into chunks and sends the overview + the chunks sharing the most character pairs with the question (≤ 16k chars; Thai-safe) — never the family's records or photos; the answer streams back, is never saved (`askAns` keeps it on the page); shares the daily cap. **Both languages** (`POST /api/b/translate {trip, day}`, `trBlock` on the record page): the day's untranslated quote/note/fav/sum/custom-first texts go to Claude in one call (Thai → en, else → th, JSON back) and each translation is saved in `entries.tr` (migration 0010) — kept while the text is unchanged, cleared by the upsert when it changes; `trLine(e)` shows it under the text in the book, the words page and the PDF. `mode: 'talk'` = three bedtime questions about the day (entry kind `talk`, id `<trip>.talk.d<i>`, one per line, migration 0011; `talkBlock` on the record page) → kid mode tile 💬 `talk` (`kidTalk`): question cards, a tap reads one aloud in its own language (`kidtalk`). Usage: table `ai_usage` (migration 0013, per family per UTC day: calls, tokens in/cached/out) — the daily cap is taken atomically there (`aiTake`, survives redeploys) and story.js `onUsage` adds each finished call's tokens; `GET /api/b/ai` (editors) → the shelf's ✨ Claude card (`aiCard`) and "Claude today n/60" on the record page (`aiToday`); optional USD estimate only when `AI_USD_PER_MTOK_IN`/`_OUT` are set. Ask-the-guide sends the stable part (overview + the asking day's plan, ≤ 8k chars, `guide.excerpt().stable`) first with `cache_control: ephemeral`, the matched chunks + question after. Offline (or the network drops mid-question) the ask box answers from the manual on the phone instead: `askOffline` strips filler words (`ASK_FILL_TH/EN`) and runs the book search (`bookFind`), showing the top sections as links — no Claude. **Tonight, Claude helps** (record page, editors, `aiGroup` in views.js): the recording comes first; every Claude block of the day sits together after it under one panel `#aipanel` (`aiPanel`): a grid of steps (`aiSteps`: photos · summary · both languages · story · questions · morning game · note for family, each with its status, `jump` to its box) and **do it all** (`aiall` in sheets.js: `aiTodo` = photos → sum → story → talk not yet done, one Claude call each via `A.photoai`/`A.story`, which return truthy when Claude finished (`A.photoai` returns the answer, so the photos go round in calls of 12 until `left` is 0, at most 10 rounds; the button's count is `aiCalls`); stops on the first failure or `aistop`; progress in `aiRun`). What travels to Claude is said once, behind the panel's ⓘ (`aiNote`); each block keeps a one-line note. `.aijump` under the day strip jumps down to the panel ("n to do"). The 21:30 record-the-day push opens `/log/<i>/ai`, which scrolls to `#aipanel` once per arrival (`aiOpened`); `main .blk` has `scroll-margin-top` so jumps land below the top bar. Trip spending summary `#/t/<trip>/spend` (`viewSpend`, editors; tile on the menu): per currency (never converted) by category with bars, day by day, the biggest items. `mode: 'letter'` (whole trip, `day: null`) = a letter from the parents to the kids for when they are older (entry kind `letter`, id `<trip>.letter.all`, migration 0014, trip-wide; `letterBlock` on the book page: editable textarea, blur saves; read-only for relatives; the PDF's last page before the back cover `.letterp`). **What our family likes** (`POST /api/b/likes`, editors; `likesBlock` at the top of the travel notebook): every trip's reviews (names, stars, tags, the kids' verdicts, notes) → Claude → saved in `settings.family_likes` for both parents (`GET /api/b/likes`, editors only — it names places from every trip, so not for relatives' groups). ## Gotchas
- Cloud sessions: `.claude/hooks/session-start.sh` runs **async** (npm install, Postgres :5432, s3rver :4569, `TEST_*` env). Before the first `npm test`, wait for it: `until [ -f /tmp/mb-session-ready ]; do sleep 1; done`.
- Don't `pkill -f`/grep-kill node servers in a shell that runs tests — kill by PID.
- `FAMILY_CODE` unset ⇒ nobody can log in (server only warns).
- Headless Chromium reports `en-US`, so tests see the English UI unless they toggle.
- Docker Hub `minio/minio` is not pullable here; tests use `s3rver` (devDependency) as the S3 emulator.
- Seeds use a mixed hand layout (pretty objects, one-line rows): edit them surgically (replace only the changed lines/keys, then `assert json.loads(new) == expected`) — `json.dump` of the whole file rewrites ~30k lines.
- Escape first, decorate never: a regex run over `esc()` output matches inside entities (`Cook's` → `&#39;` → "39" got highlighted). Match the raw text, escape each piece.
- `.pocket h5` (and other page-level rules) set `--display`, which is serif in HK — a component's own heading rule needs enough specificity (`.tale .scenes h5`).
- Kid mode opens the next trip (HK before AU): to check another book's colouring pages, render `lineArt()` on its SVGs directly.
- Tests: closed `<details>` hide their text from `innerText` — use `textContent`. Headless `speechSynthesis` exists but has no voices; assert the UI state, not the sound.
- A test that needs content not yet written: `git stash` it rather than pushing a red commit.
- Tests sign in with `page.keyboard.press('Enter')` after filling the code (the name first), never a click on the submit button: the pad auto-submits at the last digit (`pinAuto`), so the shelf can render under the click, which then lands on a book and the wait for `.shelf` times out (the "login flake" of Nov 2026). The sign-in stays busy (`loginBusy`) until the shelf has rendered, so Enter and the pad's own submit 180 ms later send one login, not two (test/story.mjs slows the state to prove it; a second CI flake of Nov 2026).
- A test that keeps the event loop busy for more than ~5 s (a long synchronous loop) makes its next `fetch` to the test server fail with "other side closed": the server dropped the idle keep-alive socket while the client could not notice. Keep in-process loops fast (the stock matcher runs a whole book in ~0.1 s).

## Debug mantra
1. **Reproduce before you fix** — see the bug on the real screen (screenshot 390 px + 1440 px, TH + EN), not just in a test.
2. **Read the data, then the code** — most "UI bugs" here were seed data (old manual, wrong key, format drift).
3. **Trust the manual, prove the fact** — every seed fact traces to the manual or the seed; grep before you ship a new one.
4. **One cause, one fix, one test** — write the test that would have caught it (it must fail on the old code).
5. **Look at both books** — HK and AU differ in theme, fonts and guides; a fix for one is checked on the other.
6. **Green CI or it didn't happen** — then check `/sw.js` on the live site and look at the live page.
