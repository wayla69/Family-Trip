# CLAUDE.md — Memory Bookshelf

Shown to users as **LifeBook** (the product name, Nov 2026: tab title, home-screen name, login page, top bar, push fallback title, PDF footer and back cover; a family may rename its own app in `#/family`, the kicker names the children); the code, docs and backup format keep the project name Memory Bookshelf (`memory-bookshelf-backup` must not change — old backups must still restore).

Family memory bookshelf for Mimi (มีมี่) and Mika (มีก้า): one book per trip. Self-hosted on **Railway**: Node 22 + **Postgres** + photos in a **Railway Storage Bucket**. The owner (Oshinei) writes Thai and wants direct execution, concise replies. UI strings are bilingual (TH/EN) through `L(th, en)`.

Read first: `docs/PRD.md` (scope, approved) · `docs/ADR.md` (stack decisions) · `docs/DESIGN.md` (look = the owner's Trip Operations Manuals) · `docs/handoff/ACCEPTANCE.md` (acceptance criteria). `README.md` is the Thai deploy/usage doc.

## Architecture (no build step, no framework)
- `server/index.js` Express: login/viewer link, `/healthz` (Postgres only — Railway's deploy health check, so a bucket outage can't block a deploy; `?full=1` adds photo storage, read by the Uptime workflow; `server/health.js`), bookshelf router, backup/import, static + SPA fallback. Refuses to boot without `DATABASE_URL`.
- `server/bookshelf.js` the API (`/api/b/*`, `/media/:id(/t)`) + `syncSeeds()`. Everything is scoped by `family_id` (one family in MVP). Writes are idempotent upserts with client ids (offline queue retries safely). mood/fav/note use deterministic ids (`<trip>.mood.d<day>.<kid>`). Table `spend` (`PUT/DELETE /api/b/spend/:id`: amount, ISO currency, category food/transport/tickets/stay/shop/other, note) = what we actually spent, typed on the record page (the parents' own ledger: the state sends it to editors only, never to a relative) (`spendBlock`; the food category offers the day's places from `spendPlaces` → `eatForDay`: plan picks, on the route, near the bed, the rest); it is in backups and the state, never in a seed or the printed book. Dark mode: `--paper #1B2230` family (lifted from near-black so cards and text read); the kids' passport covers are `.ppc.kid-<slug>` (rose / sky, soft), the generic cover sunny. `POST /api/logout` has its button at the foot of the shelf (clears the cookie and the phone's offline copy).
- `server/seeds/*.json` trips bundled with the app, in `docs/handoff/trip.schema.json` format + `theme` (DESIGN.md tokens) + per-day plan keys (→ `trip_days.plan`: timeline, moving, pick, planB, money, tips, stay, route, eat, learn, quiz, tale = the guide's story of the day `{th, en, scenes:[{e, h, th, en}]}`, a picture-book card read scene by scene by kid.js `sayTale`) + `info` (→ `trips.info` pocket guide) + `passport`. Synced on every boot; "Done" marks and app-made trips are kept. AU content was imported from the owner's *The Big Hop* artifact; a test asserts no booking refs/confirmation numbers/costs reach the state.
- `server/migrate.js` + `migrations/NNNN_*.sql` + `migrations/journal.json`: run on boot under an advisory lock; an edited applied migration is refused.
- `server/storage.js` bucket (`BUCKET`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`, `REGION`, `ENDPOINT`) or local disk. Objects `p/<trip>/<id>.jpg` + `t/…` are never public.
- Voice memos share the `media` table: `PUT /api/b/media/:id?kind=audio` keeps the clip as the phone recorded it (webm-opus / mp4-aac, ≤ 8 MB, `AUDIO_EXT`) under `a/<trip>/<id>.<ext>`, `mime` set, no thumbnail; `/media/:id` serves audio with byte ranges (Safari needs 206); backups carry them as `audio/<id>.<ext>`. Client: `isAudio`/`audioOf` vs `mediaOf` (photos only, so counts, print and share never see a clip); recorder in `clipsBlock` (`startRec`/`addClip`, 30 s cap, queued like a photo), clips play in the book day card (`noprint`) and in kid mode (`kidAudio` → `kidplay`).
- **Video clips** (owner, Nov 2026: ≤ 30 s; `server/video.js`): `PUT /api/b/media/:id?kind=video` streams the phone's file to a temporary file (≤ 400 MB, never in memory), ffmpeg (in the image and in CI) makes it an MP4 of the first 30 s, ≤ 1280 px, H.264/AAC, faststart, with **every piece of metadata dropped** (a phone writes where it was filmed — QuickTime ©xyz / ISO 6709 — and its make/model; test/bookshelf.mjs proves both gone) and a poster frame as its thumbnail (`t/<trip>/<id>.jpg`); stored `v/<trip>/<id>.mp4`, `mime` `video/mp4`, served with byte ranges like a voice memo, one clip at a time, a retry while it is being made → 503. A clip is never a photo: core.js `isVideo`/`videoOf` (`mediaOf` leaves it out — counts, print, share, kid games, the helper's photo look never see one; server photo queries use `mime LIKE 'image/%'`). Record page: "＋ คลิปวิดีโอ" beside "add photos" (`pickvideo` → `#vpick` outside `#app` → sheets.js `addVideo`, which reads the length on the phone to say "the first 30 s will be kept", queued like a photo), `vidsBlock` (player with poster, caption, delete) under the photos; the book's day page plays them (`.vclips.noprint`); kid mode's photos page too (`kidVids`). Backups carry `videos/<id>.mp4` + `videos/<id>.jpg`; the offline pack stores the posters (the clips only with "everything").
- `server/images.js` sharp: EXIF-rotate, strip all metadata/GPS, 2560 px + 520 px thumb. `server/backup.js` complete zip + idempotent restore (one object in flight at a time — `add` waits for archiver's `entry` event, else a slow download holds every photo in memory; a failed read ends the download instead of hanging it; the zip carries `profile` = the family's app name/kicker/tiles, restored where none was set; `children` rows the seeds made first get their blank birth month, look and drawn characters back through a conditional upsert, so a second restore is still a no-op) (archiver 8 is ESM-only: `const { ZipArchive } = require('archiver')` relies on Node ≥ 22.12 require(esm); the CI docker job builds a zip inside the image). `server/auth.js` family code → HMAC cookie `mb` (editor); relatives' view-only PIN `VIEW_PIN` (same pad, must differ from `FAMILY_CODE`) or link `/v/<VIEW_TOKEN>` → viewer (sees every book); **relatives in groups** (`#/viewers`, editors, `viewViewers`; table `viewer_groups`, migration 0012, not in backups): each group its own PIN (6–12 digits, stored only as `A.pinHash` = HMAC with the session secret) and/or link `/v/<random token>`, and the books ticked for it — the cookie carries the group id (6th token part), `attachUser` looks the group up (15 s cache, cleared on edit) and `A.canSee(user, trip)` scopes state, seed, media, PDF, weather and hearts; deleting a group signs its phones out, a new link kills the old (test/viewers.mjs); secret from `SESSION_SECRET` or Postgres `settings`. **The sign-in pad opens by itself at the last digit**: `/api/brand` carries `pin: {lens, open}` = the lengths a code can have (`FAMILY_CODE`, `VIEW_PIN`, each group's `viewer_groups.pin_len`, migration 0021 — never a digit); sheets.js `pinAuto` submits when the typed length is one of them and no longer one exists (`open` = a group PIN of unknown length, saved before 0021 → the button stays). ## Gotchas
- **Older iPads** (owner's family: iPad Pro 12.9" 1st gen = iPadOS 16 max, iPad mini 4 / Air 2 = iPadOS 15 max): no regex lookbehind anywhere in `public/*.js` (Safari < 16.4 refuses the whole file — test/infra.mjs guards it; views.js `splitPoints`/`splitCut`/`dropEndStop` and KEYFACT's `em` group look back by hand); `color-mix()` needs Safari 16.2 — the server serves `/app-legacy.css` (`server/legacycss.js`: each color-mix → its stronger colour) and core.js swaps it in when `CSS.supports` says no; guard Safari-15.4+ APIs (`structuredClone`); prefix `-webkit-backdrop-filter`/`-webkit-mask-image`; give `overflow-x:hidden` before `overflow-x:clip`. Check layouts at 744×1133, 768×1024, 810×1080, 820×1180, 834×1194, 1024×1366 both ways; kid mode widens to 960 px from 1000×1000.
- **Motion on iPad Safari** (Nov 2026): game motion that matters (a thing must rise, fall or arrive) runs on the Web Animations API with px values, never on CSS keyframes that read a `var()` in the `animation` shorthand or a `vh` inside a `transform` — Safari may leave them unplayed while Chromium plays them. Decoration may stay CSS (it is harmless if it does not run).
- **Never centre with `transform` in kid mode**: `.kidwrap button:active{transform:scale(.94)}` replaces any `transform` while pressed, so a button centred with `translate(-50%,-50%)` jumps half its size under the finger and the tap lands on its parent (the farm's animals did). Centre with the `translate` property (`translate:-50% -50%`, Safari 14.1+) or with margins; animate it with `transform`.
- **The tests run with reduced motion; the owner's devices do not.** A UI check of anything that moves (bubbles, confetti, the kid page's slide-in, hops) needs one scratch run with `reducedMotion: 'no-preference'` too, and a test of moving things waits for a state (`waitForFunction`, up to a few seconds), never one look after a fixed sleep (under reduced motion a bubble takes 12 s to rise; CI is slower than this box).
- **iPad in Chromium** (scratch scripts, not a substitute for Safari): `userAgent` of a Mac Safari + `maxTouchPoints` 5 + `hasTouch` + the iPad's viewport; `LEGACY=1` forces `app-legacy.css`. There is no WebKit here — after a Safari-only fix say so, ask the owner to close and reopen the Home-Screen app once or twice, and keep the fix robust rather than guessed (remove the fragile mechanism, as with the bubbles).
- test/infra.mjs "every data-a has a handler" finds an action only as `name(` at the start of a line (or `'name':`): a one-line `Object.assign(A, { name() {…} })` fails it — one action per line.
- **The branch after a squash-merge**: `origin/<branch>` still holds the merged commits, so a push of a branch reset to `main` is refused and a force-push is blocked here — `git merge -s ours origin/<branch>` (no content change), then a plain push; the PR's squash keeps `main` clean.
- Read-aloud voices (kid.js `voiceFor`): iPadOS lists novelty/robot voices (Bad News, Trinoids, Zarvox, Eddy/Rocko/Grandpa…) — `VOICE_NO` drops them, `VOICE_NICE` + Enhanced/Premium rank first; default rate .92, pitch 1.2 (the bedtime player keeps its calm .8/1.05).
- Cloud sessions: `.claude/hooks/session-start.sh` runs **async** (npm install, Postgres :5432, s3rver :4569, `TEST_*` env). Before the first `npm test`, wait for it: `until [ -f /tmp/mb-session-ready ]; do sleep 1; done`.
- Don't `pkill -f`/grep-kill node servers in a shell that runs tests — kill by PID.
- `FAMILY_CODE` unset ⇒ nobody can log in (server only warns).
- Headless Chromium reports `en-US`, so tests see the English UI unless they toggle.
- Docker Hub `minio/minio` is not pullable here; tests use `s3rver` (devDependency) as the S3 emulator.
- Seeds use a mixed hand layout (pretty objects, one-line rows): edit them surgically (replace only the changed lines/keys, then `assert json.loads(new) == expected`) — `json.dump` of the whole file rewrites ~30k lines.
- Escape first, decorate never: a regex run over `esc()` output matches inside entities (`Cook's` → `&#39;` → "39" got highlighted). Match the raw text, escape each piece.
- `.pocket h5` (and other page-level rules) set `--display`, which is serif in HK — a component's own heading rule needs enough specificity (`.tale .scenes h5`).
- Kid mode opens the next trip (HK before AU): to check another book's colouring pages, render `lineArt()` on its SVGs directly.
- Tests: closed `<details>` hide their text from `innerText` — use `textContent`. Headless `speechSynthesis` exists but has no voices; assert the UI state, not the sound.
- A test that needs content not yet written: `git stash` it rather than pushing a red commit.
- Tests sign in with `page.keyboard.press('Enter')` after filling the code (the name first), never a click on the submit button: the pad auto-submits at the last digit (`pinAuto`), so the shelf can render under the click, which then lands on a book and the wait for `.shelf` times out (the "login flake" of Nov 2026). The sign-in stays busy (`loginBusy`) until the shelf has rendered, so Enter and the pad's own submit 180 ms later send one login, not two (test/story.mjs slows the state to prove it; a second CI flake of Nov 2026). A third cause (Nov 2026, found by reproducing it): the boot's own first `load()` (no session yet) could answer 401 *after* a quick sign-in had loaded the shelf, set `S = null` and send the phone back to the sign-in page — core.js `load()` now carries a generation (`loadGen`/`loadOk`): an older load never undoes a newer one that succeeded (test/ui.mjs session `slow-boot` delays the first answer).
- A test that changes data through the API and then reloads the page must wait for the state it asserts, not for the first element: after a reload the phone draws its stored copy first (the old data), then the fresh state. test/story.mjs read "Do it all (3 steps)" on CI that way (Nov 2026: the stored copy had no photo yet; `aiallSays(n)` now waits for the count and prints the button's text).
- A test that keeps the event loop busy for more than ~5 s (a long synchronous loop) makes its next `fetch` to the test server fail with "other side closed": the server dropped the idle keep-alive socket while the client could not notice. Keep in-process loops fast (the stock matcher runs a whole book in ~0.1 s).

## Debug mantra
1. **Reproduce before you fix** — see the bug on the real screen (screenshot 390 px + 1440 px, TH + EN), not just in a test.
2. **Read the data, then the code** — most "UI bugs" here were seed data (old manual, wrong key, format drift).
3. **Trust the manual, prove the fact** — every seed fact traces to the manual or the seed; grep before you ship a new one.
4. **One cause, one fix, one test** — write the test that would have caught it (it must fail on the old code).
5. **Look at both books** — HK and AU differ in theme, fonts and guides; a fix for one is checked on the other.
6. **Green CI or it didn't happen** — then check `/sw.js` on the live site and look at the live page.
7. **The owner's screen beats Chromium** — when a photo from the iPad shows what the headless browser does not, believe the photo: rerun at that device's size with its user agent and motion setting, and when Safari still can't be reproduced, replace the fragile mechanism (CSS keyframes → Web Animations, `transform` → `translate`) instead of tuning it.
8. **A flaky test is a bug until proven otherwise** — find whether the test (a press below the fold, a star given 1.4 s later, one look at something still moving) or the app is wrong, fix that cause, and print the numbers in the test's message so the next failure explains itself. Never retry blindly or loosen the check.
