# Memory Bookshelf · ชั้นหนังสือความทรงจำของมีมี่และมีก้า

เว็บแอปครอบครัว: **หนึ่งทริป = หนึ่งเล่ม** บนชั้นหนังสือ หน้าตาแบบเดียวกับเล่ม *Trip Operations Manual* ของเรา (ปก · การ์ดวัน "01" · แผงที่ไป · ไทม์ไลน์ · กล่อง Local pick) เก็บรูป คำพูด อารมณ์ ของโปรด บันทึกพ่อแม่ และ "ครั้งแรก" ของเด็กๆ ระหว่างทริปหรือย้อนหลัง ติดตั้งเป็นแอปบนมือถือได้ (PWA) และบันทึกได้ตอนไม่มีสัญญาณ — ระบบส่งขึ้นเองเมื่อกลับมาออนไลน์
รันบน Railway: Node 22 + Postgres + Railway Bucket เก็บรูป

### เตือนก่อนทุกกิจกรรม 30 นาที
- หน้า **🗓️ วันนี้** (ผู้ใหญ่) → **🔔 เปิดการเตือน** → กดอนุญาตการแจ้งเตือน → กด **ทดสอบ** ดูว่าเด้งไหม · เปิดทีละเครื่อง (พ่อและแม่เปิดคนละเครื่องได้)
- ในวันเดินทาง แอปจะเด้งเตือน 30 นาทีก่อนทุกขั้นในไทม์ไลน์ของวันนั้น เช่น "08:00 · อีก 30 นาที — มื้อเช้าที่ Hoi Lin Tea House…" แม้ล็อกจอหรือปิดแอปอยู่ · แตะแล้วเปิดหน้าวันนั้น · ตามเวลาท้องถิ่นของทริป (วันออกเดินทาง ขั้นที่สุวรรณภูมิใช้เวลาไทย)
- **iPhone:** ต้องกดแชร์ → "เพิ่มไปยังหน้าจอโฮม" แล้วเปิดแอปจากไอคอนก่อน (iOS 16.4 ขึ้นไป) จึงจะเปิดการเตือนได้ · Android/Chrome เปิดได้เลย
- ต้องมีสัญญาณเน็ตตอนที่จะเด้ง (การเตือนมาจากเซิร์ฟเวอร์) · ข้อความเตือนมีแค่คำในแผน ไม่มีรูปหรือชื่อเด็ก · ปิดได้ที่ปุ่มเดิม

### ใช้ตอนไม่มีเน็ต (บนเครื่อง บนเรือ ในอุโมงค์)
- แอปเก็บหน้าตา ฟอนต์ และภาพวาดทั้งหมด (ตราวัน หน้าระบายสี ไกด์ ตัวการ์ตูน) ไว้ในเครื่องตั้งแต่เปิดครั้งแรก และเก็บสำเนาข้อมูลล่าสุดไว้ใน IndexedDB ของเบราว์เซอร์ → เปิดชั้นหนังสือ สมุด แผนการเดินทาง พาสปอร์ต และโหมดเด็กได้โดยไม่มีสัญญาณ (ต้องเคยเข้าด้วย PIN บนเครื่องนั้นแล้ว)
- **ก่อนขึ้นเครื่อง/ลงเรือ:** เปิดสมุด → **📴 ใช้ตอนไม่มีเน็ต → เก็บเล่มนี้ไว้ในเครื่อง** แอปจะดึงรูปย่อทุกรูป รูปโปรดขนาดเต็ม และภาพวาดของเล่มนั้นมาเก็บ (กด "รวมรูปเต็มทั้งหมด" ถ้าอยากเปิดทุกรูปเต็มจอได้) รูปที่เปิดดูแล้วจะอยู่ในเครื่องเองอยู่แล้ว
- ระหว่างออฟไลน์ บันทึกได้ทุกอย่าง (รูป คำพูด อารมณ์ ติ๊ก ระบายสี วาดรูป หัวใจ) — ทุกอย่างเข้าคิวในเครื่องและส่งขึ้นเองเมื่อมีสัญญาณ (มีป้าย "รอส่ง N" บนหัวแอป) · รูปเต็มที่ยังไม่ได้เก็บจะโชว์รูปย่อแทน
- สิ่งที่ต้องมีเน็ต: ใส่ PIN ครั้งแรกบนเครื่องใหม่ · ให้ Claude แต่งนิทาน · ดาวน์โหลด PDF · เสียงอ่าน (ใช้เสียงในเครื่อง ถ้ามือถือโหลดเสียงภาษานั้นไว้แล้วจะใช้ได้ออฟไลน์)
- เน็ตช้า: ถ้าเซิร์ฟเวอร์ไม่ตอบใน 4 วินาที แอปใช้หน้าที่เก็บไว้ก่อนแล้วค่อยซิงก์

ลิงก์จากแอปคู่มือทริป: `https://<โดเมน>/#/cap?t=hk2026&d=<วัน 0–5>` เปิดหน้าบันทึกของวันนั้น

### ย้ายข้อมูลจากแอป Harbour Hop
1. ใน Claude (บัญชีเจ้าของ Artifact) ดึงข้อมูลตาม `docs/handoff/Memory_Bookshelf_Handoff.md` §5 เก็บเป็นโฟลเดอร์: `moments.json` · `visits.json` · `days.json` · `assets/<รหัสรูป>.jpg`
2. ลองก่อน (ไม่เขียนอะไร): `node scripts/import-harbour-hop.mjs <โฟลเดอร์> --url https://<โดเมน>` → ดูจำนวนรูป/คำพูด/ครั้งแรก/ที่ไป เทียบกับปกสมุดในแอปเดิม และรายการที่ผิดรูปแบบ
3. นำเข้าจริง: เติม `--apply` · รันซ้ำได้ ไม่เกิดรายการซ้ำ · **อย่าลบข้อมูลในแอปเดิมจนกว่าตัวเลขตรงกัน**

## Deploy บน Railway (ประมาณ 15 นาที · ไม่ต้องเชื่อม GitHub กับ Railway)
**ตอนนี้ (ตั้งแต่ 18 ต.ค. 2026):** เซอร์วิสบน Railway ต่อกับ repo นี้แล้ว (Settings → Source → `wayla69/Family-Trip` branch `main`) → merge เข้า `main` = Railway deploy เอง · workflow **Deploy** ใน GitHub เหลือไว้กดเองเป็นทางสำรอง (ต้องตั้ง `RAILWAY_TOKEN` ก่อน) ไม่รันอัตโนมัติแล้ว

เดิม: GitHub ของเจ้าของ authorize แอป Railway ไม่ได้ → ใช้ GitHub Actions สั่ง Railway CLI (ขั้นตอนด้านล่างเก็บไว้เผื่อต้องกลับไปใช้)

**ใน Railway (ทำครั้งเดียว)**
1. **New Project → Empty Project** → **+ Create → Empty Service** ตั้งชื่อ `web`
2. **+ Create → Database → PostgreSQL**
3. **+ Create → Bucket** (ที่เก็บรูป เลือก region ใกล้ไทย เช่น Singapore — เปลี่ยนทีหลังไม่ได้)
4. เซอร์วิส `web` → **Variables** ใส่:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `BUCKET`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`, `REGION`, `ENDPOINT` = อ้างอิงจาก Bucket (ปุ่ม *Add Reference* → เลือก Bucket) · ถ้าแท็บ Credentials ของ Bucket บอกว่า path-style ให้เพิ่ม `BUCKET_PATH_STYLE=1`
   - `FAMILY_CODE` = **PIN ครอบครัว ตัวเลข 6 หลักขึ้นไป** (ผู้ใหญ่ใช้เข้าและบันทึก) — ใส่ครั้งเดียวต่อมือถือ เครื่องจำไว้ 400 วัน · ใส่ผิด 10 ครั้ง/เครื่อง หรือ 30 ครั้งรวมทุกเครื่องใน 10 นาที ระบบหยุดรับ PIN 10 นาที (เครื่องที่เข้าอยู่แล้วใช้ได้ตามปกติ) · หลีกเลี่ยงวันเกิดเด็กหรือเลขเรียงกัน
   - `VIEW_TOKEN` = สตริงสุ่ม (`openssl rand -hex 24`) → ลิงก์ญาติ `https://<โดเมน>/v/<VIEW_TOKEN>` (ดูอย่างเดียว)
   - `VIEW_PIN` (ไม่บังคับ) = **PIN ญาติ ดูอย่างเดียว** ตัวเลข 6 หลักขึ้นไป ต้องไม่ซ้ำกับ `FAMILY_CODE` → ญาติเปิดเว็บ ใส่ PIN นี้ที่แป้นเดียวกัน พิมพ์ชื่อตัวเองในช่อง "ชื่ออื่น" (ชื่อนี้ขึ้นบนหัวใจที่ส่งให้เด็กๆ) · ผิดซ้ำโดนล็อกเหมือน PIN ครอบครัว · เปลี่ยนค่าเมื่อไร ญาติต้องใส่ PIN ใหม่ (เครื่องที่เข้าอยู่แล้วยังใช้ได้จนคุกกี้หมดอายุ — ถ้าต้องตัดสิทธิ์ทันทีให้เปลี่ยน `SESSION_SECRET`)
   - `SESSION_SECRET` = สตริงสุ่ม (`openssl rand -hex 32`) — ถ้าไม่ใส่ ระบบสร้างและเก็บใน Postgres เอง
   - `BACKUP_TOKEN` = สตริงสุ่ม 24 ตัวขึ้นไป (สำหรับ backup อัตโนมัติ)
   - `ANTHROPIC_API_KEY` (ถ้าต้องการปุ่มให้ Claude แต่งนิทาน)
5. **Settings → Networking → Generate Domain** · ไม่ต้องใช้ Volume แล้ว (ข้อมูลอยู่ใน Postgres รูปอยู่ใน Bucket)
6. **Project Settings → Tokens → Create token** (environment `production`) — เป็น *Project token* ไม่ใช่ Account token

**ใน GitHub (ทำครั้งเดียว)** → repo → Settings → Secrets and variables → Actions
- Secret `RAILWAY_TOKEN` = token จากข้อ 6
- Variables: `RAILWAY_SERVICE` = `web` · `MB_URL` = `https://<โดเมน>`
- Actions → **Deploy** → *Run workflow* เพื่อ deploy ครั้งแรก แล้วเปิดลิงก์ ใส่ PIN (เลือก พ่อ/แม่ ได้ ไม่บังคับ)

deploy เองจากเครื่องก็ได้: `npm i -g @railway/cli@5.62.1 && railway login && railway link && railway up --service web`

บนมือถือ: iPhone → Safari → Share → *Add to Home Screen* · Android → Chrome → *Install app* · ขั้นตอนทดสอบบนมือถือ: `docs/DEVICE-QA.md`

## ความปลอดภัยของรูปเด็ก (PDPA)
- ทุกอย่างอยู่หลัง PIN ครอบครัว (cookie HttpOnly/SameSite/Secure) · รูปไม่มี URL สาธารณะ — ส่งผ่านเซิร์ฟเวอร์ให้เฉพาะคนที่ล็อกอินหรือมีลิงก์ญาติ · `noindex` ทุกหน้า
- ลิงก์ญาติเป็น **ดูอย่างเดียว** เปลี่ยนค่า `VIEW_TOKEN` เมื่อไรลิงก์เก่าใช้ไม่ได้ทันที
- เซิร์ฟเวอร์ลบตำแหน่ง GPS/EXIF ออกจากรูปทุกใบก่อนเก็บ · ไม่ส่งรูปให้ AI ใดๆ
- ล็อกอินผิดเกิน 10 ครั้ง/10 นาที ถูกบล็อกชั่วคราว
- ลบรูป = ลบไฟล์ใน Bucket จริง · ส่งออกข้อมูลทั้งหมด: `/api/b/export.json` (ข้อมูล) หรือ `/api/export.zip` (ข้อมูล + รูป)

## สำรองและกู้คืนข้อมูล
**อัตโนมัติ (แนะนำ)** — GitHub Action `Backup` ดึงสำเนาเต็ม (ข้อมูล + รูปเต็ม) ทุกวันจันทร์ 02:17 เวลาไทย เก็บเป็น artifact 90 วัน
1. Railway → service → Variables: ตั้ง `BACKUP_TOKEN` เป็นค่าสุ่มยาวๆ (ถ้ายังไม่มี)
2. GitHub → Settings → Secrets and variables → Actions → secrets `MB_URL` = `https://<โดเมน>`, `MB_BACKUP_TOKEN` = ค่าเดียวกับ `BACKUP_TOKEN` ใน Railway และ `MB_BACKUP_PASSPHRASE` = รหัสผ่านยาวๆ สำหรับเข้ารหัสไฟล์สำรอง **จดเก็บไว้นอก GitHub ด้วย** (ไม่มีรหัสนี้ เปิดไฟล์สำรองไม่ได้)
3. Actions → Backup → *Run workflow* เพื่อทดสอบครั้งแรก

ไฟล์สำรองถูกเข้ารหัส (gpg AES-256) ก่อนอัปโหลด จึงใช้ได้แม้ repo เป็น public (artifact ของ repo public ใครที่ล็อกอิน GitHub ก็โหลดได้ แต่จะได้แค่ไฟล์ที่เปิดไม่ออก) · เปิดไฟล์: `gpg -d memory-book-backup.zip.gpg > backup.zip` แล้วกู้คืนตามด้านล่าง · ถ้า secrets ไม่ครบ งานจะขึ้นสีแดง (ไม่ข้ามเงียบๆ)

นอกจากนี้ Railway Postgres มี backup ของตัวเอง (ตั้งใน Postgres → Backups)

**ทำเอง** — เปิด `https://<โดเมน>/api/export.zip` ขณะล็อกอิน เก็บไว้ที่ Google Drive / ฮาร์ดดิสก์ เดือนละครั้ง

**กู้คืน** (ผู้ใหญ่ที่เข้าด้วย PIN):
```bash
curl -c ck.txt -H 'x-mb: 1' -H 'content-type: application/json' -d '{"code":"<PIN>","name":"พ่อ"}' https://<โดเมน>/api/login
curl -b ck.txt -H 'x-mb: 1' --data-binary @memory-bookshelf-YYYY-MM-DD.zip https://<โดเมน>/api/import
```
กู้ซ้ำกี่ครั้งก็ได้ ไม่ทับข้อมูลที่มีอยู่ (เพิ่มเฉพาะที่ขาด) รูปย่อสร้างใหม่ให้เอง

## English summary
Memory Bookshelf: one book per family trip, styled like the owner's Trip Operations Manuals. Node 22 + Express + Postgres + Railway Storage Bucket, vanilla-JS PWA with an offline write queue. Deploy: Railway's GitHub connection deploys `main` (the GitHub Actions `railway up` workflow is a manual fallback). Photos are EXIF/GPS-stripped and only streamed to signed-in users. Weekly off-site backup (GPG-encrypted before upload, so a public repo is fine) and idempotent restore via `POST /api/import`.
